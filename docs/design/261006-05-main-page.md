# 설계: 메인 페이지

Magpie의 첫 화면. 전체 게임 목록과 랭킹을 한 화면에 보여준다. 상단 바와 랭킹 페이지도 이 문서에서 정한다.
랭킹 규칙과 API는 [랭킹 설계](./261006-06-ranking.md), 저장소·서버 틀은 [프로젝트 골격](./261006-04-project-skeleton.md)을 따른다.

---

## 1. 페이지

| 주소 | 화면 |
|---|---|
| `/` | 메인: 게임 목록 + 랭킹 요약 |
| `/ranking` | 랭킹 전체 (`/ranking?target=total&period=daily`) |
| `/play/:gameId` | 게임 화면 — 사과게임 설계에서 만든다 |

Vue Router의 history 모드를 쓴다. 운영 nginx는 모르는 주소를 `index.html`로 돌려준다(SPA 폴백).

---

## 2. 상단 바 (모든 페이지 공통)

```
[아이콘] Magpie     메인   랭킹                          [로그인]
```

- **왼쪽**: 로고. 아이콘 + "Magpie" 글자. 누르면 메인으로 간다.
  아이콘은 고유 아이콘이 생기기 전까지 `aviaryhub-icons/01-open-arch`(currentColor SVG)를 쓴다 (CLAUDE.md 공용 리소스 규칙).
- **가운데**: 메뉴 "메인", "랭킹". 지금 있는 페이지는 표시해준다.
- **오른쪽**:
  - 로그인 전: "로그인" 버튼.
  - 로그인 후: 원형 아바타 + 닉네임. 누르면 메뉴(닉네임 변경, 로그아웃)가 열린다.
    아바타는 닉네임 첫 글자로 직접 만든다. Google 프로필 사진은 저장하지도 보여주지도 않는다 (기술 스택 §3-8).
  - 로그인 기능은 로그인 설계에서 만든다. 이번에는 버튼 자리와 두 상태의 모양까지만 만든다.
- **모바일**: 한 줄에 다 들어간다. 닉네임 글자는 숨기고 아바타만 보인다.

## 3. 메인 (`/`)

### 3-1. 배치

PC (1024px 이상) — 두 단:

```
+-------------------------------------------+------------------+
| 게임                                       | 오늘의 랭킹       |
| +--------+ +--------+ +--------+           | [총합 v][일간|역대]|
| | 사과게임| | 수박게임| | 칼날   |           |  1  까치   2,750 |
| |        | | 준비 중 | | 준비 중 |           |  2  ...          |
| +--------+ +--------+ +--------+           |  ...             |
|                                            | 17  나     1,320 |
|                                            | [전체 랭킹 보기]  |
+-------------------------------------------+------------------+
```

- 왼쪽 게임 목록은 남는 폭을 다 쓴다(3~4열). 오른쪽 랭킹 패널은 폭 360px로 고정한다.

태블릿 (640~1023px): 게임 목록 3열, 랭킹 패널은 그 아래.
모바일 (640px 미만): 게임 목록 2열, 랭킹 패널은 그 아래.

### 3-2. 게임 카드

| 요소 | 내용 |
|---|---|
| 그림 | 게임마다 인라인 SVG 그림 (사과게임: 숫자가 적힌 사과 몇 개). 4:3 비율 |
| 이름 | 게임 목록의 `name` |
| 한 줄 설명 | `tagline` |
| 아래 줄 | "오늘 1위 142개" (기록 없으면 "오늘 첫 기록에 도전"). 로그인했으면 "내 최고 98개"도 |

- 누르면 `/play/<id>`로 간다.
- **준비 중 카드**: 1차 목록 중 아직 안 만든 게임(수박, 칼날 모으기, 숫자 던전, 설원 캠프)은 흐리게 보이고 "준비 중" 표시를 단다. 누를 수 없다.
  게임 목록의 `status`가 `coming-soon`인 게임이다.
- 사과게임도 게임 화면을 만들기 전까지는 `coming-soon`이다. 사과게임 구현 때 `playable`로 바꾼다.

### 3-3. 랭킹 패널

- 제목 "오늘의 랭킹" (역대를 고르면 "역대 랭킹").
- 대상 선택: 총합(기본) + 플레이 가능한 게임들.
- 기간 전환: **일간(기본)** | 역대.
- 상위 10명: 순위, 닉네임, 점수(단위 포함). 1~3위는 순위 숫자를 액센트 색으로 강조한다.
- 로그인했고 기록이 있는데 10위 밖이면, 목록 맨 아래에 구분선을 두고 내 줄을 붙인다.
- "전체 랭킹 보기" → `/ranking`으로, 지금 고른 대상·기간을 그대로 넘긴다.

---

## 4. 랭킹 페이지 (`/ranking`)

- **대상 탭**: 총합 + 플레이 가능한 게임들. 모바일에서는 가로로 밀어서 넘긴다.
- **기간 전환**: 일간(기본) | 역대.
- 일간이면 날짜와 초기화까지 남은 시간을 보여준다: "2026-10-06 · 초기화까지 3시간 12분".
- 총합 탭에는 설명 한 줄을 단다: "게임마다 1위를 1000점으로 환산해 더한 점수예요."
- **표**: 상위 100명. 순위, 닉네임, 점수.
- **내 순위**: 로그인했고 기록이 있으면, 화면 아래에 고정 막대로 "내 순위 17위 · 1,320점"을 보여준다.
- 고른 대상·기간은 주소 쿼리(`?target=&period=`)에 남긴다. 새로고침이나 뒤로가기를 해도 유지되고, 주소를 공유할 수 있다.

## 5. 상태별 화면

| 상태 | 화면 |
|---|---|
| 불러오는 중 | 줄 모양 회색 막대(스켈레톤) |

| 불러오기 실패 | "랭킹을 불러오지 못했어요" + 다시 시도 버튼 |

## 6. 비주얼 방향 (제안)

[컨셉 노트](../../AviaryHub-Resource/Projects/Magpie/concept.md)의 후보를 바탕으로 한다.

| 항목 | 제안 |
|---|---|
| 색 | 까치 깃털의 흑백 대비를 바탕으로, 액센트 한 가지만 쓴다: 까치 날개·꼬리의 **청록 광택** |
| 라이트 / 다크 | 둘 다 지원한다. 시스템 설정을 따른다(수동 전환은 나중에) |
| 글꼴 | Pretendard (OFL, 직접 호스팅). 점수 숫자는 자릿수가 맞게 고정폭 숫자로 쓴다 |
| 아이콘 | Phosphor (MIT). 인라인 SVG로 들어간다. 이모지는 쓰지 않는다 (CLAUDE.md §4-1) |
| 모서리 | 버튼·입력 8px, 카드·패널 12px |
| 움직임 | 마우스 올림·누름 전환 정도만 |

- 구현할 때 [AI-Reference-Pack](../../AI-Reference-Pack/README.md)의 UI 레퍼런스를 참고한다.

## 7. 구현

### 7-1. 화면 구성 요소

| 구성 요소 | 하는 일 |
|---|---|
| `TopBar` | 상단 바 |
| `UserMenu` | 로그인 버튼 / 아바타 메뉴 |
| `GameCard` | 게임 카드 |
| `RankingList` | 랭킹 목록. 패널(10명)과 페이지(100명)가 같이 쓴다 |
| `TargetSelect`, `PeriodToggle` | 대상 선택, 기간 전환 |
| `HomePage`, `RankingPage` | 페이지 |

- API 호출은 Hono RPC 클라이언트로 한다. 서버 라우트 타입이 그대로 따라온다.
- 로그인 상태는 작은 스토어(Pinia) 하나에 둔다.

### 7-2. 개발용 테스트 기록

점수 제출은 사과게임 때 만든다. 그 전까지 화면을 확인하려면 랭킹에 기록이 있어야 한다.
`pnpm db:seed-dev`(`server/scripts/seed-dev.ts`)로 **개발 DB(`magpie-dev`)에만** 가짜 유저("테스트01"~"테스트20")와 기록을 넣는다. 스키마 이름이 `-dev`로 끝나지 않으면 실행하지 않는다.
처음에는 SQL 파일로 계획했지만, 최고 기록이 판 번호(`play_id`)를 참조해야 해서 스크립트로 바꿨다.

### 7-3. 구현 순서

메인 페이지는 다른 설계에 기대므로 아래 순서로 만든다. 단계마다 커밋한다.

1. **프로젝트 골격** (04) — 빈 틀, `/health`
2. **랭킹 표와 조회 API** (06) — `users` 최소 표 포함, 개발용 테스트 기록
3. **메인·랭킹 화면** (이 문서) — 상단 바, 게임 카드, 랭킹 패널·페이지
4. 로그인 (다음 설계) — 상단 바 로그인 연결
5. 사과게임 (다음 설계) — 점수 제출, 카드를 `playable`로
