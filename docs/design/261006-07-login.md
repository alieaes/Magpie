# 설계: 로그인 (Google)

랭킹에 기록을 남기려면 유저를 구분해야 한다. Google 계정으로 로그인하고, 랭킹에는 유저가 정한 닉네임만 보인다.
기술 선택은 [기술 스택 §3-8](./261006-03-tech-stack.md)을 따른다: `openid-client` + 자체 세션.

---

## 1. 흐름

```
[로그인] → GET /auth/google → Google 로그인·동의 → GET /auth/google/callback → 세션 쿠키 → 원래 보던 화면
```

1. 상단 바 "로그인" → `/auth/google?returnTo=<지금 주소>`.
2. 서버가 임시 값(state, nonce, PKCE 코드)을 만들어 10분짜리 쿠키에 넣고 Google로 보낸다.
3. Google이 `/auth/google/callback`으로 돌려보내면, 서버가 임시 값을 맞춰보고 코드를 토큰으로 바꾼 뒤 ID 토큰을 검증한다. `openid-client`가 처리한다.
4. ID 토큰의 `sub`(Google 계정 고유 ID)로 유저를 찾고, 없으면 만든다.
5. 세션을 만들고 쿠키를 준 뒤 `returnTo`로 보낸다. `returnTo`는 우리 사이트 안의 경로(`/`로 시작)만 받는다.

**Google에 요청하는 범위는 `openid` 하나다.** 이메일·이름·프로필 사진을 요청하지 않으므로 받지도 저장하지도 않는다.

---

## 2. 세션

| 항목 | 값 |
|---|---|
| 쿠키 | `magpie_session`. HttpOnly, SameSite=Lax, Path=/, 운영에서는 Secure |
| 값 | 무작위 32바이트. DB에는 **SHA-256 해시만** 저장한다 (DB가 새도 세션을 쓸 수 없게) |
| 기간 | 30일. 남은 기간이 15일 아래로 내려간 상태에서 요청이 오면 30일로 다시 늘린다 |
| 로그아웃 | 세션 줄을 지우고 쿠키를 지운다 |

표 `002_sessions.sql`:

| 열 | 내용 |
|---|---|
| `id_hash` | 세션 값의 SHA-256 (기본 키) |
| `user_id` | `users.id` |
| `created_at`, `expires_at` | UTC |

- 나중에 실시간 서버(채팅·멀티)도 같은 쿠키와 같은 표로 유저를 확인한다.
- 만료된 세션은 서버가 하루 한 번 지운다.

**요청 위조 방지**: 상태를 바꾸는 요청(로그아웃, 닉네임 변경, 점수 제출)은 POST/PUT + JSON 본문으로만 받고,
`Origin` 헤더가 우리 사이트가 아니면 거절한다. SameSite=Lax 쿠키라 다른 사이트의 폼 전송에는 쿠키가 실리지 않는다.

---

## 3. 닉네임

- 처음 로그인하면 닉네임이 없다(`NULL`). 화면에 "닉네임 정하기" 창이 뜬다.
- **닉네임을 정하기 전에는 점수를 제출할 수 없다.** 연습 플레이는 된다.
- 규칙: 앞뒤 공백을 지우고 **2~12자**, 한글(완성형·자모)·영문·숫자·밑줄(`_`)만. 공백은 쓸 수 없다.
  대소문자만 다른 닉네임도 중복으로 본다(DB 정렬 규칙이 대소문자를 구분하지 않음).
- 쓸 수 없는 이름: 운영자 사칭을 막는 짧은 목록(`관리자`, `운영자`, `admin`, `magpie` 등). 목록은 `shared/`에 둔다.
- 변경: 상단 메뉴 "닉네임 변경"에서 언제든. 지난 기록의 이름도 같이 바뀐다(랭킹은 `users`에서 이름을 붙이므로).

---

## 4. API

| 요청 | 하는 일 |
|---|---|
| `GET /auth/google?returnTo=` | Google 로그인으로 보낸다 |
| `GET /auth/google/callback` | 로그인 마무리, 세션 쿠키 발급, `returnTo`로 이동. 실패하면 `/?login=failed` |
| `POST /auth/logout` | 로그아웃 |
| `GET /api/me` | `{ "user": { "nickname": "까치" } }` 또는 `{ "user": null }`. 닉네임 전이면 `nickname: null` |
| `PUT /api/me/nickname` | `{ "nickname": "..." }`. 규칙 위반 `400`, 중복 `409` |

랭킹 API의 `me`(내 순위)는 이 세션으로 채워진다. 지금의 `getSessionUserId`(항상 null)를 세션 확인으로 바꾼다.

---

## 5. 화면

- 상단 바 "로그인" 버튼을 켠다. 로그인 후에는 아바타 + 닉네임, 메뉴(닉네임 변경, 로그아웃)가 동작한다.
- 닉네임 정하기 창: 입력칸 하나, 규칙 안내 한 줄, 중복이면 그 자리에서 알려준다.
- 로그인 실패(`?login=failed`)면 상단에 짧은 안내를 띄운다.

---

## 6. 유저가 해야 할 일 (Google Cloud Console)

비밀값이라 제가 대신 만들 수 없다.

1. **OAuth 클라이언트 ID 만들기** (유형: 웹 애플리케이션).
   기존 클라이언트(Falcon·Crash)를 같이 쓰면 Google 동의 화면에 그 앱 이름이 떠서 헷갈린다. **Magpie용으로 새로 만드는 것을 추천**한다.
2. 승인된 리디렉션 URI:
   - `http://localhost:5480/auth/google/callback` (개발)
   - `https://magpie.aviaryhub.org/auth/google/callback` (운영)
3. 동의 화면이 "테스트" 상태면 테스트 사용자로 등록한 계정만 로그인된다. 공개하려면 "게시"로 바꾼다.
   `openid` 범위만 쓰므로 민감한 범위가 아니다.
4. 발급된 클라이언트 ID와 시크릿을 `server/.env`의 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`에 직접 넣는다. 대화에는 붙이지 않는다.

## 9. 구현 메모 (2026-10-08)

- `GET /api/me` 응답에 `loginAvailable`을 더했다. `.env`에 `GOOGLE_CLIENT_ID`·`GOOGLE_CLIENT_SECRET`이 둘 다 있을 때만 `true`이고, 화면의 로그인 버튼이 이 값으로 켜진다.
- 쿠키 이름: https 사이트에서는 `__Host-magpie_session`, `__Host-magpie_oauth`. 같은 `aviaryhub.org` 아래 다른 서비스가 상위 도메인 쿠키로 덮어쓰지 못하게 한다. 개발(http)에서는 접두사 없이 쓴다.
- 로그인 도중 값(state, nonce, PKCE, 돌아갈 주소)은 10분짜리 쿠키에 둔다. Google 계정 고르기 화면을 항상 띄운다(`prompt=select_account`).
- Google OIDC 설정은 첫 로그인 때 받아 기억한다(서버 시작이 Google 응답에 묶이지 않게).
- 요청 위조 방지는 `/api/*`, `/auth/*`의 POST·PUT·DELETE에 Origin 확인으로 걸었다. 개발 중에는 `localhost:5480`으로 접속해야 한다(`127.0.0.1`은 Origin이 달라 막힌다).
- 로그인 실패 안내는 `?login=failed`, 설정 없음은 `?login=unavailable`.
- 만료 세션은 서버 시작 때와 하루에 한 번 지운다.
- 닉네임을 바꾸면 그 서버 프로세스의 랭킹 캐시를 바로 비운다.
