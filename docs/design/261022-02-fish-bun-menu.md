# 설계: 붕어빵 가게 — 메뉴 늘리기 (슈크림·피자 붕어빵)

[붕어빵 가게](./261021-01-fish-bun.md)는 지금 팥 붕어빵 하나다. 평판이 오르면 **슈크림 붕어빵**과 **피자 붕어빵**이 열리고,
손님이 메뉴를 골라 주문한다. 어떤 반죽을 얼마나 부을지가 새로운 판단이 된다. [261021-03 §5](./261021-03-fish-bun-growth.md)의 2차 후보 "메뉴 늘리기"를 구체화한다.

---

## 1. 메뉴

| 메뉴 | 열리는 때 | 재료비 | 빵 값 (알맞음, 레시피 0단계) | 굽기 (화력 50% 기준) |
|---|---|---|---|---|
| 팥 | 처음부터 | 50원 | 120원 | 덜 익음 0~4초, 알맞음 4~6.5초 (지금과 같음) |
| 슈크림 | 평판 Lv3 | 70원 | 160원 | **빨리 익고 빨리 탄다**: 덜 익음 0~3.5초, 알맞음 3.5~5.5초 |
| 피자 | 평판 Lv5 | 90원 | 200원 | **오래 익는다**: 덜 익음 0~5초, 알맞음 5~8초 |

- 메뉴는 평판 레벨로 저절로 열린다. 강화로 사지 않는다. 그날 아침 평판 레벨로 정하므로 하루 동안은 바뀌지 않는다.
- 반죽 레시피 강화(+20원/단계)는 모든 메뉴의 빵 값에 더한다. 빵틀 길들이기(+0.4초/단계)는 모든 메뉴의 알맞음 구간을 늘린다.
- 황금 후보는 메뉴와 상관없이 부을 때 정한다. 황금이면 그 메뉴 빵 값의 3배. 반짝이는 0.6초는 그 메뉴가 알맞음에 들어설 때 시작한다.
- 재료비·값·시간은 튜닝값이다. §6의 흉내 플레이어로 맞춘다.

---

## 2. 붓기 (반죽 고르기)

- 빵틀 판 위쪽에 **반죽 고르기 버튼**을 둔다: [팥] [슈크림] [피자] (열린 메뉴만). 지금 고른 반죽이 빈 틀에 부어진다. 하루를 시작하면 팥.
  메뉴가 하나만 열려 있으면 버튼을 숨긴다(지금 화면과 같음).
- 쓸어 넘기기로 여러 칸에 부어도 같은 반죽이 들어간다.
- 빵틀 왼쪽 위에 **메뉴 표시**(작은 아이콘: 팥 콩, 슈크림 크림 방울, 피자 조각)를 붙인다. 뒤집은 붕어빵은 겉모습이 같아서 이것으로 구분한다.
- 부은 반죽(위에서 본 모습)은 속이 보인다: 팥은 검붉은 팥소, 슈크림은 노란 크림, 피자는 빨간 소스와 치즈·피망 조각.

---

## 3. 진열대

- 진열대는 한 칸에 섞여 쌓이고, **메뉴마다 먼저 꺼낸 빵부터** 나간다. 최대 개수는 메뉴를 합친 수다(진열대 강화 그대로).
- 화면에서는 메뉴별로 모아(팥 → 슈크림 → 피자) 보여 준다. 아이콘에 메뉴 표시를 붙인다(품질 표시는 그대로).
- [탄 빵 버리기]는 메뉴 상관없이 탄 빵을 모두 버린다.

---

## 4. 주문과 판매

- 손님마다 **메뉴 한 가지**를 N개 주문한다. 여러 메뉴를 섞은 주문은 나중에 검토한다.
- 말풍선에 메뉴 아이콘과 개수를 보여 준다. 대사도 메뉴를 말한다("슈크림 두 개 주세요").
- 주문 메뉴 비율(튜닝값):

| 열린 메뉴 | 팥 / 슈크림 / 피자 |
|---|---|
| 팥 | 100 / – / – |
| 팥·슈크림 | 65 / 35 / – |
| 팥·슈크림·피자 | 50 / 28 / 22 |

- **[N개 주기]**는 주문한 메뉴의 진열대 빵을 준다. 그 메뉴 빵이 모자라면 꺼지고 "슈크림 1개 부족"처럼 알려 준다. **[+1 덤]**은 같은 메뉴로 한 개 더.
- 다른 메뉴를 주면 **불만**이다(평판 −3, 콤보 0, 받는 돈 절반). 보통 손님은 버튼이 주문한 메뉴만 주므로 이런 일이 없고,
  메뉴를 직접 골라야 하는 특별 손님([261022-03](./261022-03-fish-bun-special-customers.md))에서 생긴다.
- 먹방 크리에이터는 지금처럼 품질은 따지지 않지만 메뉴는 주문한 대로 받아야 한다.

## 5. 로직

| 항목 | 변경 |
|---|---|
| 빵틀 | `filling`(0 팥, 1 슈크림, 2 피자)을 더한다 |
| 붓기 입력 | `tap` 값 = 빵틀 번호 + 16 × 메뉴. 팥은 지금 값과 같다. 열리지 않은 메뉴는 `locked_menu` |
| 익힘 | 메뉴별 알맞음 시작·탐 시작 값 (§1) |
| 진열대 | 빵 = { 메뉴, 품질 }. 판매는 그 메뉴의 앞쪽부터 |
| 판매 입력 | `sell` 값 = 8 × 메뉴 + 자리 × 2 + 덤. 팥은 지금 값과 같다. 진열대에 그 메뉴가 모자라면 `no_stock` |
| 손님 | `filling`(주문 메뉴)을 더한다. 뽑는 순서: 종류 → 메뉴 → 개수 |
| 정산 | 메뉴별 판매 개수를 정산표에 더한다 |

- 저장 형식은 바뀌지 않는다(메뉴는 평판 레벨로 열린다).
- 손님 뽑기 순서가 바뀌므로 **배포하는 순간 진행 중이던 하루**는 서버 재계산이 맞지 않아 저장되지 않을 수 있다. 하루가 3분이라 영향은 작다.

---

## 6. 밸런스

- 흉내 플레이어가 진열대와 주문을 보고 모자란 메뉴를 붓도록 고친다. 30일을 다시 돌려 기존 목표(1일째 수익, 빵틀 9·12칸 시점)가 크게 바뀌지 않는지, Lv5 이후 하루 수익이 오르는지 본다.

---

## 7. 테스트

- 메뉴별 익힘 구간(덜 익음·알맞음·탐 경계), 메뉴별 재료비·빵 값, 황금 창이 메뉴의 알맞음 시작에 맞는지.
- 열리지 않은 메뉴 붓기 `locked_menu`, 메뉴별 선입선출 판매, 그 메뉴 부족 `no_stock`, 다른 메뉴를 주면 불만.
- 지금(팥만) 기록이 같은 결과를 내는지(입력 값이 그대로).
