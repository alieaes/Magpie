# 설계: 게임 랭킹 초기화 (관리자)

[게임 분류](./261022-07-game-categories.md)의 전체 랭킹은 날마다 초기화하지 않는다.
시즌을 새로 시작하거나 게임 수치를 크게 바꾼 뒤처럼 필요할 때, **관리자만** 그 게임의 랭킹을 비운다.

---

## 1. 하는 일

- 그 게임의 `best_alltime` 줄을 모두 지운다. 그 뒤 끝나는 하루부터 다시 쌓인다.
- 바꾸지 않는 것: 판 기록(`plays`, `play_replays`), 가게 저장(`game_saves`), 다른 게임의 랭킹. **가게는 그대로 이어서 한다.**
- 화면에서 되돌리는 기능은 없다. 판 기록이 남아 있으므로 꼭 필요하면 손으로 되살릴 수 있다(통과한 판 중 초기화 시각 전 유저별 최고).
- 게임 분류에만 쓴다. 미니게임은 일간이 매일 새로 시작하고 역대는 쌓이는 것이 규칙이라 대상이 아니다.

---

## 2. 서버

| 요청 | 성공 | 실패 |
|---|---|---|
| `POST /api/admin/games/:gameId/reset-ranking` | `204` | 없는 게임 `404 NOT_FOUND`, 미니게임 `400 BAD_REQUEST`("미니게임 랭킹은 초기화할 수 없어요"), 이미 비어 있음 `409 RANKING_EMPTY` |

- 기존 관리자 API와 같다: 비로그인 `401`, 관리자가 아니면 `403`, 요청 위조 방지(Origin 확인).
- 한 트랜잭션(`server/src/admin/service.ts`의 `resetGameRanking`):
  1. 그 게임의 줄을 잠그고 읽는다(`SELECT user_id ... WHERE game_id = ? FOR UPDATE`, 순위 색인 `ix_best_alltime_rank`를 탄다).
  2. 기본 키로 지운다(틈 잠금을 피한다. 탈퇴처럼 500개씩).
  3. `admin_actions`에 남긴다.
- 처리 뒤 그 프로세스의 랭킹 캐시를 비운다.
- 동시에 끝나는 하루: 1번 전에 들어온 기록은 같이 지워지고, 그 뒤 들어온 기록은 새 랭킹의 첫 기록이 된다.

### 작업 기록

- `action = 'reset_ranking'`, `target_user_id`·`play_id`는 NULL, `detail = { gameId, removed }`(지운 줄 수).
- 지운 줄을 통째로 남기지 않는다. 판 기록으로 다시 만들 수 있고, 탈퇴한 유저의 점수가 작업 기록에 남지 않게 하기 위해서다.
- 새 마이그레이션 `db/008_admin_reset_ranking.sql`: `admin_actions.action` ENUM에 `reset_ranking`을 더한다. `server/src/db/types.ts`의 `AdminActionKind`도.

---

## 3. 화면

- **랭킹 페이지에서, 관리자이고 게임 분류 탭일 때만** 시간 줄 오른쪽에 [랭킹 초기화] 버튼(작은 버튼, 빨강 글씨). 메인 패널에는 없다.
- 누르면 확인 창(`ConfirmDialog`):
  - 제목 "랭킹 초기화"
  - "붕어빵 가게 랭킹을 초기화할까요? 12명의 기록이 지워지고, 가게 저장은 그대로예요. 되돌릴 수 없어요." (N은 지금 보이는 참여자 수)
  - 버튼 "초기화"(빨강). 처리 중에는 버튼이 꺼지고 닫히지 않는다. 실패하면 서버 문구를 창 안에 보여준다(기존 관리 작업과 같은 흐름).
- 처리하면 랭킹을 다시 불러온다.
- 참여자가 0명이면 버튼을 끈다.

## 5. 테스트

- 서버
  - 권한: 비로그인 `401`, 일반 유저 `403`, 다른 Origin `403`.
  - 없는 게임 `404`, 미니게임 `400`, 비어 있으면 `409`.
  - 초기화하면 그 게임의 전체 랭킹이 비고, 가게 저장·판 기록·다른 게임 랭킹은 그대로. `admin_actions`에 `{ gameId, removed }`.
  - 초기화 뒤 하루를 끝내면 그 기록이 새 랭킹 1위로 들어간다.
- 화면: 관리자로 랭킹 페이지 붕어빵 가게 탭 → 초기화 → 목록이 빈다. 미니게임 탭과 일반 유저에게는 버튼이 없다. 폰·PC.

## 6. 검토한 대안

| 대안 | 내용 | 판단 |
|---|---|---|
| 명령으로만 (`pnpm admin:reset-ranking <gameId>`) | 화면에서 잘못 누를 일이 없다 | 다른 관리 작업(기록 삭제)과 같이 화면에서 하고, 확인 창으로 막는다 |
| 시즌 표로 시작 시각만 바꾸기 | 지난 시즌 랭킹을 다시 볼 수 있다 | 최고 기록 표가 시즌별 최고를 들고 있지 않아 새 표와 갱신 경로가 필요하다. 지난 시즌 보기가 필요해지면 다시 본다 |
| 미니게임 역대에도 열기 | 같은 기능으로 역대도 비울 수 있다 | 요청 범위 밖. 필요하면 같은 API에 미니게임을 허용하면 된다 |
| "N일부터 집계" 표시 | 언제 초기화됐는지 알 수 있다 | 이번에는 넣지 않는다. 작업 기록에서 마지막 초기화 시각을 읽어 붙일 수 있다 |

## 8. 구현 메모 (2026-10-22)

- 기본 키를 500개씩 나누는 `chunks`는 탈퇴(`server/src/auth/account.ts`)에만 있던 것을 `server/src/lib/chunks.ts`로 옮겨 같이 쓴다.
- 테스트는 `server/test/admin.test.ts`가 아니라 `server/test/saves.test.ts`에 두었다. 초기화는 그 게임의 랭킹 줄을 통째로 잠그고 지우는데,
  성장형 시험 게임 기록을 쓰는 저장 테스트와 다른 파일로 병렬로 돌면 되돌림 트랜잭션끼리 잠금이 엇갈려 교착이 났다. 같은 파일에 두어 차례로 돌린다.
  작업 기록 detail을 읽는 `parseDetail`은 `server/test/helpers.ts`로 옮겼다.
- Origin 확인은 `/api/*` 전체에 걸린 미들웨어가 하고 `auth-routes.test.ts`가 본다. 이 API만 따로 시험하지 않았다.
- 확인: 서버 테스트(권한·404·400·409, 초기화 뒤 저장·판 기록·사과게임 그대로, 작업 기록, 다음 하루가 새 1위) 통과.
  화면은 확인용 서버에서 테스트 계정 2명이 붕어빵 가게 하루를 끝내 전체 랭킹 2명을 만든 뒤, 관리자(테스트1, 확인 뒤 해제)로
  버튼(미니게임 탭에는 없음, 0명이면 꺼짐) → 확인 창 문구 → 초기화(`204`) → 빈 목록, 저장(2일째)은 그대로인 것을 봤다.
