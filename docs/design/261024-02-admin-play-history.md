# 설계: 관리자 대시보드 — 게임별 플레이 이력

[관리자 대시보드](./261024-01-admin-dashboard.md)에 게임별 최근 판을 보여준다. 로그인한 판과 비로그인 판을 따로 보여준다.

| 구분 | 한 줄 |
|---|---|
| 로그인 | `10.24 14:03   테스트03 (203.0.113.7)   142개` |
| 비로그인 | `10.24 14:03   203.0.113.7   142개` |

지금은 둘 다 만들 재료가 없다.

- 판 기록(`plays`)에 IP가 없다.
- 비로그인은 연습 모드(미니게임)·체험(성장형)이라 서버에 아무것도 남지 않는다.

그래서 둘 다 새로 남긴다. 배포 전 판은 IP가 "-"로 나오고, 비로그인 이력은 배포한 뒤부터 쌓인다.

---

## 1. IP

- 읽는 곳은 하나(`server/src/lib/client-ip.ts`, 새): Cloudflare가 붙이는 `CF-Connecting-IP` → 없으면 연결 주소(개발 중 `127.0.0.1`·`::1`).
- 운영은 Cloudflare → nginx → API 서버(127.0.0.1)라 연결 주소는 늘 nginx다. nginx는 받은 헤더를 그대로 넘기므로 nginx 설정은 바꾸지 않는다.
- Cloudflare를 거치지 않고 서버 PC로 바로 오면 이 헤더를 꾸밀 수 있다. 관리자가 보는 값과 비로그인 기록의 횟수 제한(§3)에만 쓰고, 권한에는 쓰지 않는다.
- 최대 45자(IPv6) 문자열로 둔다.

---

## 2. 로그인 판

- `plays`에 `ip` 열을 더한다. 판을 열 때(`POST /api/plays`), 체험 이어받기는 받을 때(`POST /api/plays/adopt-trial`) 적는다.
- **보여주는 판: 끝난 판**(`ended_at`이 있음). 최근에 끝난 순.
  - 통과한 판: 점수.
  - 거절된 판: 점수 자리에 "거절 · 사유". 사유 문구는 `bad_input` 입력 이상, `time` 시간 안 맞음, `mismatch` 점수 다름, `stale_save` 저장 바뀜, `admin` 관리자가 지움.
  - 안 끝내고 버려진 판(`abandoned`)은 끝난 시각이 없어 나오지 않는다.
- 닉네임은 지금 닉네임이다(바꿨으면 바뀐 이름, 초기화됐으면 "이름 없음"). 탈퇴하면 판이 같이 지워지므로 목록에서도 빠진다.
- 게임별 최근 순으로 읽도록 `plays`에 색인 (`game_id`, `ended_at`)을 더한다.

---

## 3. 비로그인 판

- 연습 모드(미니게임)·체험(성장형) 판이 끝나면 화면이 점수를 서버에 보낸다.
  로그인했지만 닉네임을 정하기 전인 판도 연습 모드라 여기 들어간다. 개발용 `?seed=` 판은 보내지 않는다.
- **점수는 화면이 보낸 값 그대로다(서버가 다시 계산하지 않는다).** 0 ~ 그 게임의 이론상 최고 점수(`maxScore`)만 받는다.
- 보내기에 실패해도 화면은 아무것도 하지 않는다(다시 보내지 않고, 결과 화면도 그대로다).

| 요청 | 본문 | 응답 |
|---|---|---|
| `POST /api/plays/practice` | `{ gameId, score }` | `204`. 기록할 수 없는 게임·점수 범위 밖 `400 BAD_REQUEST`, IP당 분당 30회 초과 `429 TOO_MANY_REQUESTS` |

- 로그인과 상관없이 받는다. 요청 위조 방지(Origin 확인)는 다른 POST처럼 받는다.
- 횟수 제한은 판 시작과 같은 `RateLimiter`(프로세스 메모리), 키는 IP.

### 표 `practice_plays` (새)

| 열 | 내용 |
|---|---|
| `id` | BIGINT AUTO_INCREMENT |
| `game_id` | VARCHAR(32) |
| `score` | INT. 화면이 보낸 점수 |
| `ip` | VARCHAR(45) |
| `created_at` | DATETIME(3), UTC. 받은 시각 |

- 색인 (`game_id`, `id`). 유저와 이어지지 않는다(누구 판인지 모른다).

---

## 4. 관리자 API

`GET /api/admin/plays?gameId=apple-ten&who=member|guest&cursor=`

- 50개씩, 최근 순. 다음 50개는 응답의 `nextCursor`를 `cursor`로 보내 받는다(더 없으면 `null`). 새 판이 들어와도 겹치거나 빠지지 않게 위치(커서)로 넘긴다.
- `who=member`(로그인) 항목: `{ playId, at, nickname, ip, score, rejectReason }`. `at`은 끝난 시각(ISO UTC), 거절된 판은 `score`가 `null`이고 `rejectReason`이 있다. 닉네임이 없으면 `nickname: null`, 배포 전 판은 `ip: null`.
- `who=guest`(비로그인) 항목: `{ id, at, ip, score }`. `at`은 받은 시각.
- 기록할 수 없는 게임이거나 `who`가 틀리면 `400 BAD_REQUEST`. 권한은 기존 관리자 API와 같다(`401`/`403`).
- 형식은 `shared/src/admin.ts`의 `AdminPlaysResponse`.

## 5. 화면

대시보드의 방문자 칸 아래.

```
┌ 플레이 이력 ──────────────────────────────────────────────────┐
│ [사과게임] [복권 긁기] [붕어빵 가게] [분식집]                     │
│                                                                 │
│ 로그인                          │ 비로그인                      │
│ 10.24 14:03 테스트03            │ 10.24 14:05 203.0.113.9       │
│             (203.0.113.7)  142개│                         98개  │
│ 10.24 13:58 까망이              │ 10.24 13:40 198.51.100.4      │
│             (198.51.100.2)      │                        121개  │
│               거절 · 시간 안 맞음 │                              │
│ ...                             │ ...                           │
│          [더 보기]              │          [더 보기]            │
└─────────────────────────────────────────────────────────────────┘
```

- 게임 탭: 기록할 수 있는 게임(지금 사과게임·복권 긁기·붕어빵 가게·분식집). 처음에는 첫 게임.
- PC는 로그인·비로그인 두 칸을 나란히, 폰은 로그인 위·비로그인 아래.
- 시간은 KST `MM.DD HH:mm`. 점수는 천 단위 쉼표와 게임 단위(개·원, `findGame().scoreUnit`).
- 거절된 판은 점수 자리에 "거절 · 사유"(흐린 빨강). 닉네임이 없으면 "이름 없음", IP가 없으면 "-".
- 각 칸 50개, 아래 [더 보기]로 50개씩 더. 더 없으면 버튼을 숨긴다. 비었으면 "아직 없어요."
- 탭을 바꾸면 두 칸을 새로 불러온다.

## 7. 테스트

- 서버
  - IP: `CF-Connecting-IP`가 있으면 그 값, 없으면 연결 주소.
  - 판을 열면 `plays.ip`가 채워진다. 체험 이어받기도.
  - `POST /api/plays/practice`: 비로그인도 `204`, 점수 범위 밖·없는 게임 `400`, 같은 IP 31번째 `429`.
  - `GET /api/admin/plays`: 비로그인 `401`, 일반 유저 `403`, 틀린 게임·`who` `400`.
    로그인 판은 끝난 판만 최근 순(버려진 판 빠짐), 거절 사유와 닉네임. 비로그인 판도 최근 순. 커서로 받은 다음 50개가 앞과 겹치지 않는다.
- 화면: 비로그인으로 사과게임·붕어빵 가게 체험을 끝내면 비로그인 칸에, 기록 모드 판은 로그인 칸에 나온다. 탭 바꾸기, 더 보기. 폰·PC.

---

## 8. 주의할 것

- **IP는 개인정보다.** 지금은 지우지 않고 계속 쌓인다. 탈퇴하면 로그인 판은 같이 지워지지만, 비로그인 판은 누구 것인지 모르므로 남는다.
  보관 기간이 필요해지면 하루 한 번 정리(`server.md`)에 붙이면 된다.
- 비로그인 기록은 누구나 보낼 수 있고 점수도 꾸밀 수 있다. 랭킹과는 상관없고 대시보드에만 보인다.

---

## 9. 검토한 대안

| 대안 | 내용 | 판단 |
|---|---|---|
| 비로그인 판도 서버가 시드를 주고 다시 계산 | 비로그인 점수도 믿을 수 있다 | 비로그인 판마다 판 열기와 입력 기록 전송이 필요하다. 보기용이라 이번에는 점수만 받는다 |
| 거절된 판은 빼고 통과한 판만 | 목록이 짧다 | 이상한 판을 찾는 데 쓸 수 있어 사유와 함께 보여준다 |
| 페이지 번호(몇 쪽) | 원하는 쪽으로 바로 간다 | 판이 계속 들어오면 쪽이 밀려 겹친다. [더 보기]로 충분하다 |

## 10. 구현 메모 (2026-10-24)

- 판 서비스 `start`·`adoptTrial`이 IP를 마지막 인자로 받고(없으면 NULL), 비로그인 점수는 같은 서비스의 `recordPractice`가 남긴다(테스트 시계를 같이 쓰려고).
- 게임 탭은 랭킹 탭의 `TargetTabs`를 그대로 쓰고 총합만 뺐다. 탭 묶음의 화면 읽기 이름을 바꿀 수 있게 `label`(기본 "랭킹 대상")을 더했다.
- **설계에 없던 변경: 하루 지난 판 정리(`abandonStalePlays`)를 "먼저 읽고 기본 키로 고치기"로 바꿨다.**
  새 테스트 파일이 더해지자 전체 테스트에서 이 정리 테스트가 매번 교착(Deadlock)으로 실패했다. 조건 UPDATE가 대기 판 색인(`status, started_at`) 범위에 틈 잠금을 걸어,
  같은 때 판을 열거나 끝내는 다른 트랜잭션과 엇갈린 것이다. 스펙의 잠금 규칙(판 시작·관리자 기록 삭제가 이미 쓰는 방식)대로 바꾸고 500개씩 나눈다. 운영에서도 하루 한 번 도는 정리가 판 저장과 엇갈릴 수 있던 자리다.
- 테스트 닉네임은 겹치지 않게 시각을 붙인다(고정 이름 하나가 반복 실행 중 한 번 "이미 쓰는 닉네임"으로 실패했다).
- 확인: 서버 테스트(IP 읽기, 판·체험 이어받기의 IP, 비로그인 점수 204·400·429, 이력 권한·400, 끝난 판만·거절 사유·지금 닉네임, 같은 시각 커서, 비로그인 50개씩) 통과. 전체 서버 테스트 5번 연속 통과.
  화면은 확인용 서버에서 관리자로 지정한 테스트1(확인 뒤 해제)로 기록 모드 사과게임 한 판(IP 127.0.0.1), 로그아웃 뒤 연습 한 판(204)을 끝내 두 칸에 나오는 것,
  거절된 판 "거절 · 시간 안 맞음", 탭 바꾸기, 시험용 비로그인 판 55개(확인 뒤 지움)로 [더 보기] → 55줄·버튼 사라짐을 PC·폰에서 봤다. 체험(성장형) 하루 끝의 점수 보내기는 화면에서 끝까지 해 보지 않았다(코드·스펙만).
