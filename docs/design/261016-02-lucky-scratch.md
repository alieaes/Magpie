# 설계: 복권 긁기 (`lucky-scratch`)

즉석복권을 긁는 게임. 복권 10장을 받고 시작해서, 당첨금으로 복권을 더 사 긁거나 원할 때 정산한다.
**정산한 소지금이 점수**가 되어 랭킹에 오른다. 점수 제출은 [판 기록과 점수 제출](./261006-08-play-submission.md)을 그대로 따른다.

실존 복권(스피또, 로또 등)의 이름·디자인은 쓰지 않는다. 게임 안 복권 이름은 자체 브랜드 **"까치 즉석복권"** 으로 한다
(까치 = Magpie. 까치가 울면 반가운 소식이 온다는 길조라 복권과도 맞는다).

---

## 1. 규칙

| 항목 | 값 |
|---|---|
| 시작 | 복권 10장, 소지금 0원 |
| 복권 한 장 | 3 × 3칸, 은박으로 덮여 있다. **같은 그림 3개가 나오면 그 그림의 등수로 당첨** |
| 당첨 | 당첨금이 바로 소지금에 들어간다 |
| 구매 | 소지금으로 한 장 1,000원. 1장 / 5장 / 10장 단위로 산다. 언제든 살 수 있다 |
| 한 판 상한 | 복권 200장(받은 10장 포함) |
| 시간 | 5분. 끝나면 그 자리에서 정산한다 |
| 끝 | "정산하기", 시간 종료, 파산(남은 복권 0장 + 소지금 1,000원 미만), 200장을 다 긁음, 화면이 가려짐 |
| 점수 | 끝났을 때의 소지금(원) |
| 긁지 않은 복권 | 끝날 때 남아 있으면 **무효**(점수에 안 들어간다) — §1-2 |

### 1-1. 당첨표

| 등수 | 그림 | 당첨금 | 확률 | 기대 당첨금 |
|---|---|---|---|---|
| 1등 | 까치 | 10,000,000원 | 0.001% (10만 장에 1장) | 100원 |
| 2등 | 왕관 | 1,000,000원 | 0.01% (1만 장에 1장) | 100원 |
| 3등 | 보석 | 50,000원 | 0.2% (500장에 1장) | 100원 |
| 4등 | 클로버 | 5,000원 | 5% (20장에 1장) | 250원 |
| 5등 | 복주머니 | 1,000원 (본전) | 30% | 300원 |
| 꽝 | — | 0원 | 64.789% | — |

- 한 장의 기대 당첨금은 **850원**(가격의 85%). 사면 살수록 평균적으로는 잃는다. 실제 복권처럼 "언제 멈출까"가 이 게임의 판단이다.
- 랭킹은 **가장 잘한 판 하나**로 매기므로, 크게 걸었을 때 크게 따는 판이 위로 간다. 평균이 손해여도 더 긁을 이유가 생긴다.
- 확률과 금액은 튜닝값이다. 상금 상한은 DB 점수 열(INT, 약 21억) 안에 들어가게 잡았다: 200장 × 1등 1천만 원 = 20억.

시뮬레이션(20만 판, 표 기준):

| 전략 | 한 판 평균 장수 | 3만 원 이상 판 | 10만 원 이상 | 100만 원 이상 |
|---|---|---|---|---|
| 받은 10장만 긁고 정산 | 10장 | 2.1% | 0.12% | 0.10% |
| 3만 원 넘으면 정산, 아니면 계속 사기 | 22장 | 4.5% | 0.25% | 0.23% |
| 10만 원 넘을 때까지 계속 | 27장 | 0.8% | 0.50% | 0.29% |

받은 10장만 긁으면 중간값이 5,000원이다. 한 판은 보통 1~2분이다.

### 1-2. 긁지 않은 복권을 무효로 하는 이유

정산할 때 남은 복권을 자동으로 계산해 주면, "시작 → 바로 정산 → 다시 하기"를 반복하는 쪽이 직접 긁는 것보다 훨씬 빨리 복권을 많이 뽑는다
(판 시작은 분당 20회까지라 분당 200장, 직접 긁으면 분당 60~70장). 긁는 게 게임인데 안 긁는 쪽이 유리해진다. 그래서 **긁은 복권만 소지금에 들어간다**.

- 남은 복권이 있을 때 게임 안 "정산하기"를 누르면 "남은 복권 N장은 무효가 돼요"라고 한 번 묻는다.
- 셸의 "끝내기"·시간 종료·화면 가려짐은 묻지 않고 바로 끝난다(남은 복권 무효). 시작 화면 규칙 설명에 적어 둔다.

## 2. 로직 (`games/lucky-scratch/src/logic`)

순수 TypeScript, 정수 연산과 시드 난수만 쓴다. 서버도 이 코드로 재계산한다.

| 함수 | 하는 일 |
|---|---|
| `drawTicket(seed, index)` | `index`번째 복권(0부터)의 등수·당첨금·9칸 그림을 만든다. 시드 난수는 `"${seed}#${index}"`로 장마다 따로 만든다 |
| `replay(seed, inputs)` | 입력을 차례로 적용해 점수(소지금)와 마지막 틱을 낸다 |

**복권 만들기**

1. 등수: 0 ~ 999,999 중 하나를 뽑아 당첨표 구간에 넣는다(1등 10, 2등 100, 3등 2,000, 4등 50,000, 5등 300,000, 나머지 꽝).
2. 그림: 그림은 5종(등수마다 하나).
   - 당첨: 당첨 그림 3개 + 나머지 4종을 각각 2개씩 넣은 8개 중 섞어서 6개.
   - 꽝: 5종을 각각 2개씩 넣은 10개 중 섞어서 9개. 어떤 그림도 3개가 되지 않는다.
   - 9칸을 섞어서 배치한다. 섞기는 시드 난수로 하는 Fisher–Yates.
3. 그래서 당첨 복권은 3개짜리 그림이 정확히 하나, 꽝은 하나도 없다. 꽝에도 "까치 2개" 같은 아까운 판이 자연스럽게 나온다.

**입력 기록**

```json
[{ "t": 312, "op": "scratch" }, { "t": 2050, "op": "buy", "count": 5 }, ...]
```

| 입력 | 뜻 | 실패 사유 |
|---|---|---|
| `scratch` | 다음 복권을 다 긁었다. 그 복권의 당첨금이 소지금에 들어간다 | 남은 복권이 없음 `no_ticket`, 직전 긁기와 15틱(0.25초) 미만 간격 `too_fast` |
| `buy` | `count`장(1~10)을 산다 | 소지금 부족 `no_money`, 200장 초과 `ticket_limit` |

- `t`는 그 일이 일어난 틱. 늘어나기만 해야 하고 18,000(5분)을 넘으면 안 된다(`bad_tick`).
- 점수 = 마지막 입력을 적용한 뒤의 소지금. 남은 복권은 셈하지 않는다(§1-2).
- 기록은 최대 390개(긁기 200 + 사기 190). `maxTicks` 18,000, `maxScore` 2,000,000,000.
- 긁기 간격 0.25초는 사람 손으로는 넘을 수 없는 하한이다. 화면의 "한 번에 긁기"도 이보다 오래 걸린다.

## 3. 화면 (`/play/lucky-scratch`, `games/lucky-scratch/src/scene`, Phaser 4)

### 3-1. 배치

```
가로(PC)                                              세로(모바일)
+------------------------------+--------------------+  +----------------------+
|  +------------------------+  |  소지금             |  |  +----------------+  |
|  | [까치] 까치 즉석복권     |  |  125,000원          |  |  |  까치 즉석복권  |  |
|  | 같은 그림 3개면 당첨!    |  |                    |  |  |  [ 3 x 3 은박 ] |  |
|  | 1등 까치  10,000,000   |  |  남은 복권  ||| 7장  |  |  |  당첨표         |  |
|  | ...                    |  |                    |  |  +----------------+  |
|  |  +------+------+------+ |  |  [1장 1,000원]      |  |  소지금 125,000원     |
|  |  | 은박 | 은박 | 은박 | |  |  [5장] [10장]       |  |  남은 복권 7장        |
|  |  +------+------+------+ |  |  [한 번에 긁기]      |  |  [1장][5장][10장]     |
|  |  | ...                | |  |                    |  |  [한 번에 긁기]       |
|  |  +------+------+------+ |  |  최근: 꽝 5등 꽝 4등 |  +----------------------+
|  | No. 0042-3F9A          |  |  긁은 23장 · 당첨 8회 |
|  +------------------------+  |                    |
+------------------------------+--------------------+
```

- 캔버스를 크게 잡고 화면에 맞춰 줄인다(Scale FIT). 사과게임처럼 영역 비율에 따라 가로·세로 배치를 바꾼다.
- 남은 복권은 카드 뒤에 겹쳐 쌓인 모양으로 보여 준다. 장수가 줄면 쌓인 두께도 준다.
- 상단 바(셸)에는 남은 시간 막대와 **소지금**을 보여 준다(§4의 `scoreLabel`).

### 3-2. 복권 카드

- 짙은 남색 바탕 + 금색 테두리. 머리에 까치 문장과 "까치 즉석복권", "같은 그림 3개면 당첨!".
- 당첨표 줄(그림 · 등수 · 금액)을 카드 안에 넣는다. 당첨되면 그 등수 줄이 빛난다.
- 아래에 일련번호(시드와 장 번호로 만든 장식 문자열).
- 그림 5종(까치·왕관·보석·클로버·복주머니)은 자체 제작 SVG를 텍스처로 만든다. 등수별 색: 1등 금색, 2등 보라, 3등 하늘, 4등 초록, 5등 빨강.
- 이모지는 쓰지 않는다. 그림은 아이콘 수준의 선 그림이 아니라 그라데이션·하이라이트·외곽선을 넣은 작은 일러스트로 그린다(§3-6).

### 3-3. 긁기

- 9칸을 은박 한 장이 덮는다. 은박은 은색 그라데이션 + 비스듬한 광택이 천천히 지나가고, "긁어 주세요" 무늬가 찍혀 있다.
- 드래그(마우스·터치)로 동전 모양 붓이 지나간 자리를 지운다. 빠르게 움직여도 끊기지 않게 지나간 길을 촘촘히 찍는다.
- 지운 자리에서 은박 부스러기가 튀어 떨어진다.
- 칸마다 얼마나 긁었는지 세어서 절반쯤 긁히면 그 칸 은박이 마저 사라진다. 9칸이 다 드러나면 결과를 낸다.
- **한 번에 긁기**(버튼, PC는 스페이스): 은박을 대각선으로 쓸어 내며 약 0.6초에 다 드러낸다.

### 3-4. 결과 연출

| 결과 | 연출 |
|---|---|
| 꽝 | 칸이 살짝 어두워지고 빨간 "꽝" 도장이 비스듬히 찍힌다 |
| 5등·4등 | 맞은 3칸에 등수 색 테두리가 빛나고, "4등 당첨 +5,000원" 띠. 동전이 소지금 쪽으로 날아가고 숫자가 올라간다 |
| 3등 | 위 + 반짝이 조각이 터진다 |
| 2등·1등 | 위 + 화면이 금빛으로 번쩍, 색종이가 쏟아지고 화면이 살짝 흔들린다. "대박! 1등 당첨" 큰 띠 |

- 결과를 1.2초 보여 준 뒤(탭하면 바로) 카드가 옆으로 날아가고 다음 복권이 쌓인 데서 올라온다.
- 남은 복권이 없으면: 소지금이 1,000원 이상이면 "복권을 다 긁었어요" + [1장 더] [5장] [10장] [정산하기]. 1,000원 미만이면 "복권을 살 돈이 없어요"를 보여 주고 끝난다.

### 3-5. 소리

녹음 파일 없이 Web Audio로 그 자리에서 합성한다. 원작·상용 효과음을 가져오지 않아도 되고, 내려받을 파일이 없다.

| 때 | 소리 |
|---|---|
| 긁는 중 | 은박 긁는 "사각사각". 걸러 낸 잡음을 붓 속도에 맞춰 크게·작게 하고, 멈추면 바로 끊는다 |
| 칸이 저절로 벗겨짐 | 짧은 "샥" |
| 구매 | 금전등록기 "철컥-칭" |
| 꽝 | 도장 찍는 "쿵" + 낮게 내려가는 두 음 |
| 5등·4등 | 밝은 짧은 아르페지오 + 동전 "띵" (동전 수만큼, 음이 조금씩 올라감) |
| 3등 | 더 긴 아르페지오 + 반짝이는 소리 |
| 2등·1등 | 팡파르(화음 진행) + 동전 쏟아지는 소리 |
| 버튼 | 작은 "톡" |

- 게임 안에 소리 켜기·끄기 버튼을 두고, 고른 값은 브라우저에 기억한다(저장이 안 되는 환경이면 켜짐으로 시작).
- 브라우저 정책상 첫 터치·클릭 전에는 소리를 낼 수 없다. "시작" 버튼이 첫 클릭이라 판 시작과 함께 소리를 연다.

### 3-6. 그림

- 까치: 옆모습으로 앉은 자세. 검은 머리·등, 흰 배와 어깨 무늬, 청록 광택이 도는 긴 꼬리(실제 까치 생김새).
- 왕관: 금색 몸체에 보석 세 개, 위쪽 끝에 진주.
- 보석: 여러 면으로 깎은 하늘색 다이아몬드, 면마다 밝기를 달리한다.
- 클로버: 네 잎, 잎마다 가운데 잎맥과 하이라이트.
- 복주머니: 빨간 비단 주머니, 금색 끈과 매듭, 금색 무늬 띠.
- 까치 문장(카드 머리), 동전, 은박 무늬도 같은 방식으로 그린다. 화면에서 직접 확인하면서 다듬는다.

### 3-7. 조작 반응성

사과게임에서 "반응이 느리다"는 의견이 있었다. 측정해 보니 프레임(60fps)과 입력 처리(0.3ms 미만)는 문제가 없었고,
원인 후보는 (1) 캔버스가 마우스 포인터보다 몇 프레임 늦게 그려지는 화면 반영 지연, (2) 사과 **중심**이 사각형에 들어가야 선택되는 판정
(사과 오른쪽 아래를 눌러 시작하면 그 사과가 빠진다), (3) 지워진 사과가 0.26초 동안 남아 보이는 것이다. 복권은 처음부터 이렇게 만든다.

- Phaser를 저지연 캔버스(`desynchronized`)로 띄운다. 그리기가 브라우저 합성 단계를 덜 거친다.
- 누르는 순간 그 자리부터 바로 긁힌다(움직여야 시작하지 않는다). 소리도 누르는 순간 난다.
- 붓은 입력 이벤트가 올 때마다 바로 찍고, 이전 위치와 사이를 메워 빠르게 그어도 끊기지 않는다.
- 판정은 너그럽게: 칸은 절반쯤 긁히면 벗겨진다. 붓은 보이는 동전 크기보다 판정이 조금 넓다.
- 버튼은 누르는 즉시 눌린 모양이 되고, 결과 연출 중에도 탭하면 바로 다음 복권으로 넘어간다. 연출이 입력을 막지 않는다.
- 소리는 저지연 모드(`latencyHint: 'interactive'`)로 연다.

사과게임 쪽 수정은 이 문서 범위가 아니다(게임끼리 독립, CLAUDE.md §4-3). 따로 다룬다.

### 3-8. 그 밖에

- 시간은 실제 경과 시간(`performance.now`)으로 틱을 센다. 18,000틱이 되면 끝.
- 화면이 가려지면(`visibilitychange` → hidden) 판을 끝낸다. 사과게임과 같은 방식이고, 그 시점의 소지금으로 바로 기록된다.
- 판 바탕·패널 색은 셸의 CSS 변수에서 읽어 라이트·다크 모드를 따른다. 복권 카드 자체는 두 모드에서 같은 디자인이다.
- 게임 영역에서는 페이지가 스크롤되지 않는다(셸이 이미 `touch-action: none`).

## 6. 테스트

- 같은 시드·같은 장 번호 → 같은 복권.
- 많은 시드로 돌려서: 당첨 복권은 3개짜리 그림이 정확히 하나이고 그게 등수 그림이다. 꽝은 3개짜리 그림이 없다.
- 등수 분포가 당첨표와 대략 맞는다(표본 20만 장, 허용 오차 안).
- `replay`: 소지금 부족 구매, 남은 복권 없이 긁기, 200장 초과, 너무 빠른 긁기, 틱 역행·5분 초과는 실패. 남은 복권은 점수에 안 들어간다.
- 화면에서 쌓은 점수 = 기록 재생 점수(같은 입력 기록).

## 7. 막지 못하는 것

- **시드를 알면 앞으로 나올 복권을 미리 계산할 수 있다.** 지금 구조는 판을 열 때 시드를 클라이언트에 주므로,
  코드를 뜯어보는 사람은 "몇 장 뒤에 2등이 있다"를 알고 딱 좋은 때에 정산할 수 있다. 사과게임은 판이 다 보이는 게임이라 문제가 없었지만, 복권은 다르다.
- 막으려면 서버가 복권을 한 장씩 내줘야 한다(긁을 때마다 요청). 공통 흐름(시드 + 끝에 재계산)과 다른 API가 필요해서 이번에는 하지 않는다.
  봇 문제([plays.md](../spec/plays.md) "막지 못하는 것")와 같은 급으로 보고, 문제가 되면 따로 설계한다.

## 9. 구현 메모 (2026-10-17)

설계대로 만들었고, 설계에 적지 않았던 세부를 아래처럼 정했다. 확정 규칙은 [스펙 lucky-scratch.md](../spec/lucky-scratch.md).

- **당첨표 그림·글자는 카드 바탕 텍스처에 미리 굽는다.** 카드마다 글자 객체 10개를 만들던 것을 없애, 다음 장을 놓을 때 할 일을 줄였다(§3-7). 당첨 때 켜는 강조 테두리만 카드마다 만든다.
- **캔버스는 불투명하게 띄우고 바탕을 셸의 `--bg`로 칠한다.** 저지연 캔버스(`desynchronized`)는 불투명할 때 효과가 확실하다.
- **결과에서 당첨이 아닌 그림은 투명도 대신 어둡게 누른다.** 크림색 칸 위에서 투명도를 낮추면 그림이 바래 보였다.
- 결과를 보는 중에는 "한 번에 긁기" 버튼이 "다음 복권"으로 바뀐다. 스페이스도 같다.
- 확인 창은 게임 안 "정산하기"에만 있다. 셸의 "끝내기"는 사과게임과 같이 바로 끝난다.
- 그림·동전·아이콘 SVG는 쓰는 크기(칸 140px, 당첨표 60px, 동전 56px)로 따로 굽는다. 크게 구워 많이 줄이면 테두리가 거칠어진다.
- 화면 검증: 연습 모드로 기록을 쌓은 뒤 같은 로직(`replay`)으로 다시 돌려 점수가 같은지 브라우저에서 확인했다(긁기 12번 + 사기 2번, 8,000원 일치).
- 사과게임 조작감 원인 후보(§3-7)는 사과게임 쪽에서 따로 확인해야 한다. 이 작업에서는 사과게임 코드를 건드리지 않았다.
