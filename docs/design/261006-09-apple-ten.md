# 설계: 사과게임 (`apple-ten`)

첫 게임. 규칙 조사는 [수록 게임 §3-1](./261006-01-game-catalog.md). 점수 제출은 [판 기록과 점수 제출](./261006-08-play-submission.md)을 따른다.

---

## 1. 규칙

원작(フルーツボックス) 규칙을 그대로 따른다.

| 항목 | 값 |
|---|---|
| 판 | 17 × 10 = 사과 170개. 사과마다 1~9 |
| 조작 | 드래그로 사각형을 그린다. 사각형 안 사과의 합이 **정확히 10**이면 그 사과들이 사라진다 |
| 빈칸 | 이미 사라진 칸은 사각형에 들어가도 된다 (0으로 친다) |
| 점수 | 사라진 사과 1개당 1점. 0~170 |
| 시간 | 120초. 끝나면 판이 끝난다 |
| 끝내기 | 더 만들 조합이 없을 때를 위해 "끝내기" 버튼 |

- 판은 시드로 만든다. 칸마다 1~9를 고르게 뽑는다. 원작도 다 풀 수 있는 판을 보장하지 않는다.
- 사각형에 들어가는 사과: 사과의 **중심**이 사각형 안에 있으면 들어간 것으로 본다.

---

## 2. 로직 (`games/apple-ten/logic`)

순수 TypeScript, 정수 연산만 쓴다. 서버도 이 코드로 재계산한다.

| 함수 | 하는 일 |
|---|---|
| `createBoard(seed)` | 17 × 10 판을 만든다 |
| `trySelect(board, rect)` | 칸 좌표 사각형 `{ c1, r1, c2, r2 }` 안의 합이 10이면 그 칸들을 비우고 지운 개수를 돌려준다. 아니면 0 |
| `replay(seed, inputs)` | 입력을 차례로 적용해 점수와 마지막 틱을 낸다 |

**입력 기록**: 합이 10이 되어 실제로 사과가 지워진 선택만 남긴다. `[{ "t": 1520, "c1": 3, "r1": 2, "c2": 5, "r2": 2 }, ...]`

- `t`: 그 선택이 일어난 틱(1/60초 단위). 늘어나기만 해야 하고 7200을 넘으면 안 된다.
- 좌표는 화면 픽셀이 아니라 **칸 번호**다. 화면 크기·회전과 상관없이 같은 기록이 나온다.
- 한 번에 최소 2개가 지워지므로(9가 최대라 1개로는 10이 안 됨) 기록은 최대 85개다.
- 기록 속 선택이 지우는 사과가 없으면(합이 10이 아님) 조작으로 보고 판을 거절한다.

## 3. 화면 (`/play/apple-ten`, `games/apple-ten/scene`)

```
+----------------------------------------------------+
| 사과게임          [=========-----] 87초      점수 64 |
|                                                    |
|   (5)(7)(6)(8)(3)(2)(9)(1)(4)(6)(5)(7)(2)(3)(8)... |
|   ... 17 × 10 판 ...                               |
|                                                    |
|                                   [끝내기]          |
+----------------------------------------------------+
```

- **시작 전**: 규칙 한 줄("합이 10이 되게 드래그해서 묶어요") + "시작" 버튼. 로그인 안 했으면 "연습 모드 · 로그인하면 기록이 남아요".
- **플레이**: 위에 남은 시간 막대와 점수. 드래그하는 동안 사각형을 청록 점선으로 그린다. 합계는 보여주지 않는다(원작과 같음).
  지워지면 사과가 살짝 튀어 오르며 사라진다.
- **끝**: 점수, (기록 모드면) 오늘 순위와 최고 기록 갱신 여부, "다시 하기", "랭킹 보기".
- **화면 방향**: 가로가 기본. 세로 모바일에서는 판을 10 × 17로 돌려서 그린다. 로직 좌표는 그대로다.
- **크기**: Phaser 화면 맞춤(FIT). PC는 가운데에 놓고 여백을 둔다.
- **터치**: 판 위에서는 페이지가 스크롤되지 않게 한다.
- **화면이 가려지면**(탭 전환, 앱 전환) 판을 그대로 끝낸다. 제한 시간 게임이라 멈춤을 허용하면 시간 검사가 깨지고, 생각할 시간을 벌 수 있기 때문이다.
- 그림: 사과는 로비 카드와 같은 모양(빨간 원 + 잎 + 흰 숫자)을 Phaser 도형으로 그린다. 소리는 이번 범위에 넣지 않는다.

## 4. 게임 패키지 구조

```
games/apple-ten/
  package.json        @magpie/game-apple-ten. 의존: @magpie/shared, phaser (scene만)
  src/logic/          createBoard, trySelect, replay, 입력 스키마
  src/scene/          Phaser 씬
  src/index.ts        클라이언트가 동적 import하는 진입점
  test/               로직 테스트
```

- 서버는 `@magpie/game-apple-ten/logic`만 가져다 쓴다(Phaser는 서버에 들어가지 않는다).
- 클라이언트 `/play/:gameId` 페이지는 게임 id로 패키지를 동적 import해서 화면 영역에 붙인다.
  게임을 띄우고 내리는 공통 방식(`mount`/`destroy`, 끝났을 때 결과 전달)은 `shared/src/game-module.ts`에 정한다.

---

## 5. 테스트

- 같은 시드 → 같은 판.
- 합이 10일 때만 지워지고, 빈칸은 0으로 친다.
- 기록 재생 점수 = 플레이하며 쌓은 점수.
- 틱이 줄어들거나 7200을 넘거나, 안 지워지는 선택이 섞인 기록은 실패.
- 서버: 시작 → 끝 흐름, 각 거절 사유, 최고 기록 갱신.

## 8. 구현 메모 (2026-10-07)

- **연습 모드만 먼저 만들었다.** 기록 모드는 로그인([07](./261006-07-login.md))과 점수 제출([08](./261006-08-play-submission.md))이 필요하다.
  로그인은 Google OAuth 클라이언트가 있어야 해서, 그 둘이 들어올 때 붙인다. 연습 모드 시드는 셸이 만든다(`randomSeed`).
- **시작·결과 화면과 점수·시간 막대는 셸(`client/src/pages/PlayPage.vue`)이 그린다.** §3은 게임 화면 안에 있는 것처럼 적었지만,
  다른 게임도 그대로 쓰고 글꼴·다크 모드를 사이트와 맞추려고 나눴다. 게임(Phaser)은 판만 그리고 `onHud`·`onEnd`로 알린다.
  보이는 동작은 §3과 같다.
- 셸과 게임의 약속은 `@magpie/shared/game-module`(`mount` → `finish`·`destroy`). 브라우저 타입을 써서 서버가 가져가는 `@magpie/shared`와 분리했다.
- 시드 난수는 `shared/src/random.ts`(문자열 → cyrb128 해시 → xoshiro128**). 정수 연산만 쓴다.
- 로직에 `isValidRect`(판 안·순서 확인)를 더했다. `replay` 실패 사유: `too_many_inputs`, `bad_tick`, `bad_rect`, `no_match`.
- 개발 중에는 `/play/apple-ten?seed=...`로 같은 판을 다시 띄울 수 있다(운영 빌드에서는 무시).
- Phaser(약 1.4MB, 압축 360KB)는 "시작"을 누를 때 받는다. 메인 화면 번들에는 들어가지 않는다.
