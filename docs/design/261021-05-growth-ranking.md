# 설계: 성장형 게임 랭킹 (게임 공통)

[성장형 게임](./261021-04-game-save.md)은 강화가 쌓일수록 점수가 오른다. 오래 한 사람이 유리하다는 점에서 미니게임 랭킹과 성격이 다르다.
이 문서는 성장형 게임의 게임별 랭킹 점수와 총합 랭킹 처리를 정한다. 첫 사례는 [붕어빵 가게](./261021-01-fish-bun.md)다.

---

## 1. 게임별 랭킹

- 점수 = **하루 수익**(그날 판의 점수, 매출 − 재료비, 0 미만이면 0).
- 기존 최고 기록 표(`best_daily`, `best_alltime`)를 그대로 쓴다. DB·API 변경이 없다.
  - 일간: 오늘 가장 많이 번 하루. KST 00:00에 새로 시작한다.
  - 역대: 지금까지 가장 많이 번 하루.
- 강화가 많이 된 가게가 유리하다. 성장형 랭킹은 "그날 장사 실력 + 가게를 키운 정도"를 함께 보는 것으로 받아들인다.
- 랭킹 화면에서 이 게임 탭을 고르면 설명 한 줄: "하루 장사로 가장 많이 번 날의 수익이에요".

---

## 2. 총합 랭킹

- 총합은 게임별 순위를 환산점(1위 1,000점)으로 바꿔 더한다([ranking.md](../spec/ranking.md)). 성장형을 넣으면 플레이 시간을 많이 쓴 사람이 총합에서도 1,000점을 가져간다.
- **성장형 게임은 총합에서 뺀다.** `GameMeta.kind`가 `'growth'`인 게임은 총합 계산에 들어가지 않는다.
- 랭킹의 대상 탭(총합 + 게임들)에는 그대로 나온다.
- 총합 탭 설명을 "미니게임마다 1위를 1,000점으로 환산해 더한 점수예요"로 바꾼다.

---

## 3. 검토한 대안

| 대안 | 내용 | 판단 |
|---|---|---|
| 가게 규모 랭킹 | 저장의 누적 매출이나 평판으로 줄 세운다 | 새 표와 갱신 경로가 필요하다. 하루 수익 랭킹을 써 본 뒤 다시 본다 |
| 강화 보정 점수 | 하루 수익을 강화 수준으로 나눠 실력만 비교한다 | 보정식이 임의적이고 유저에게 설명하기 어렵다 |
| 총합에 포함 | 순위 환산이라 금액 규모 차이는 문제가 없다 | 실력 비교와 시간 투자 비교가 섞인다 |

---

## 4. 변경

| 위치 | 변경 |
|---|---|
| `shared/src/games.ts` | `GameMeta.kind?: 'minigame' \| 'growth'`(없으면 미니게임) |
| `server/src/ranking/queries.ts` | 총합 계산에서 성장형 게임을 뺀다 |
| `client` 랭킹 패널·페이지 | 총합 설명 문구, 성장형 게임 탭 설명 |
| `docs/spec/ranking.md` | 구현 뒤 총합 규칙에 성장형 제외를 적는다 |

---

## 5. 테스트

- 성장형 게임 기록이 있어도 총합 점수·참여자 수에 들어가지 않는다.
- 성장형 게임 탭은 하루 수익 기준으로 줄 선다.
