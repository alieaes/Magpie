# 설계: 분식집 키보드 걷기 반응 — 되돌아서기와 조작 줄

상태: 컨펌(2차), 구현함 (§8 구현 메모)

장사 화면에서 방향키로 좌우를 빠르게 오가면 직원이 늦게 따라오고, 누른 키가 가끔 씹힌다.
좌우를 오가는 것은 미뤄 두지 않고 그 자리에서 바로 돌아서게 한다. 걷는 중이라 바로 못 하는 조작만 순서대로 줄을 세우고, 버리는 경우는 줄이 가득할 때 하나뿐이다.

---

## 1. 지금 (원인)

- 걸음 하나(기본 9틱 = 0.15초, 운동화·직원으로 최소 4틱)가 끝날 때까지 다른 입력을 받지 않는다(`busy`, [분식집 스펙 입력](../spec/snack-bar.md)).
- 그 사이 누른 조작은 **하나만** 미뤄 둔다(`DayView.pending`). 한 걸음 안에 두 번 누르면 앞의 것이 덮여 사라진다. **씹힘**은 이것이다.
- 반대 방향도 걷던 걸음이 끝나야 움직인다. 좌우를 오갈 때 누를 때마다 최대 0.15초 늦다. **늦는 느낌**은 이것이다.
- 누르고 있으면 계속 걷기: 걸음이 끝나는 순간 키가 눌려 있으면 바로 다음 걸음을 간다. 운동화로 걸음이 0.08초까지 짧아지면 보통으로 톡 누른 것(0.08~0.1초)도 두 칸을 간다.

## 2. 다른 게임은 어떻게 하나

| 게임·자료 | 걷는 중(움직이는 중)에 누른 키 | 누르고 있기 |
|---|---|---|
| 팩맨 아케이드 ([Pac-Man Dossier](https://pacman.holenet.info/)) | 갈림길 가운데 몇 픽셀 앞에서 미리 꺾기를 받는다(늦게 꺾을수록 1픽셀에 1프레임 손해). 방향을 빠르게 되돌리는 "헤드 페이크"가 공략법으로 나온다(걷는 중 즉시 되돌아서는지는 문서에 없음) | 누르고 있으면 계속 |
| 포켓몬 에메랄드 ([pokeemerald 디컴파일](https://github.com/pret/pokeemerald), `field_player_avatar.c`) | 받지 않는다. 걸음이 끝날 때 눌려 있는 방향만 본다(걷는 중 톡 누른 것은 사라짐) | 서 있을 때 다른 방향을 톡 누르면 돌아서기만 |
| RPG Maker MV ([corescript](https://github.com/rpgtkoolmv/corescript), `Game_Player.js`) | 받지 않는다. 움직이지 않을 때 눌려 있는 방향을 본다 | 칸마다 눌려 있으면 계속 |
| 스네이크 라이브러리 ([lt-snake](https://lt-snake.readthedocs.io/en/latest/_modules/snake/game.html)) | 순서대로 줄(최대 5개), 가득하면 새것 버림. 막힘·반대 판단은 줄에서 꺼낼 때 | - |
| 격자 게임 입력 글 ([pancelor](https://pancelor.bearblog.dev/input-buffering-for-grid-games/)) | 한 칸 미뤄 두기를 권한다. 긴 줄은 플레이어를 헷갈리게 한다고 본다. 톡 누른 것이 누르고 있는 키에 덮이지 않게 따로 둔다 | 톡 누른 것이 먼저 |
| Dis Pontibus 2 ([개발 일지](https://marcosd.itch.io/dis-pontibus-2/devlog/293219/input-queues)) | 순서대로 줄을 써 봤더니 "머리가 계획을 잊어서" 움직임이 엉뚱했다. 하나만 미뤄 두고 지금 움직임 그림을 빨리 끝내는 쪽으로 정했다 | - |
| 테트리스 가이드라인 ([Tetris wiki](https://tetris.wiki/Tetris_Guideline)) | 바쁜 시간이 없어 누르면 바로 움직인다 | 누르고 167ms(10프레임) 뒤부터 반복(DAS) |

정리하면:

- 움직임에 시간이 드는 게임에서 걸음보다 빨리 누르면, **버리거나 늦게 하거나** 둘 중 하나다. 둘 다 없는 게임(테트리스, 퍼즐 게임)은 누르는 순간 로직이 끝나고 그림만 따라간다. 분식집은 걸음 시간이 운동화로 줄이는 비용이라 이 방식을 쓸 수 없다. 걸음을 빨리 그려도 로직의 걸음 시간은 그대로라 늦음이 줄지 않는다.
- 미뤄 두기는 대부분 한 개이고(포켓몬·RPG Maker는 아예 없음), 줄을 길게 두면 손을 뗀 뒤에도 옛 조작이 이어져 헷갈린다는 경험담이 있다.
- 미뤄 두지 않아도 되는 조작은 미루지 않는 것이 씹힘을 없애는 가장 확실한 길이다. 분식집에서는 반대 방향이 그렇다(걸어온 만큼만 되돌아가면 시간 계산이 맞다). 팩맨도 방향을 빠르게 되돌리는 조작을 받아 준다.
- 누르고 있기는 짧은 지연 뒤에 시작한다(테트리스 167ms).

## 3. 줄 크기 비교

넓은 바닥에서 지금 방식과, 되돌아서기 + 줄 N개를 흉내 냈다([`keysim2.mjs`](./assets/261023-05-snack-bar-key-response/keysim2.mjs), 기본 걸음 0.15초, 1프레임 = 1틱). 칸은 "씹힌 수 / 마지막으로 누른 뒤 더 움직인 시간".

| 누르는 모양 | 지금 | 줄 1 | **줄 3** | 줄 무한 |
|---|---|---|---|---|
| 좌우 12번, 0.1초 간격 | 3 / 0.1초 | 0 / 0 | **0 / 0** | 0 / 0 |
| 같은 방향 6번, 0.1초 간격 | 1 / 0.1초 | 1 / 0.1초 | **0 / 0.25초** | 0 / 0.25초 |
| 같은 방향 10번, 0.08초 간격 | 3 / 0.15초 | 3 / 0.15초 | **1 / 0.45초** | 0 / 0.6초 |
| 계단(왼·위 번갈아) 8번, 0.1초 간격 | 2 / 0.05초 | 2 / 0.05초 | **0 / 0.35초** | 0 / 0.35초 |
| 왼 왼 스페이스, 0.07초 간격 | 1 / 0.02초 | 1 / 0.02초 | **0 / 0.17초** | 0 / 0.17초 |
| 스페이스 8번, 0.07초 간격 | 2 / 0.03초 | 2 / 0.03초 | **0 / 0.23초** | 0 / 0.23초 |

- 좌우 연타는 되돌아서기만으로 씹힘·늦음이 모두 없어진다. 미뤄 두지 않으니 줄 크기와 상관없다.
- 같은 방향·꺾기·행동은 걸음이 끝나야 할 수 있으니 미뤄 둘 수밖에 없다. 줄 3이면 위 경우가 모두 들어가고, 손을 뗀 뒤 더 움직이는 것은 0.45초까지다.
- 줄 3에서 씹히는 것은 초당 12번으로 같은 방향을 계속 누를 때뿐이다(걷는 속도의 두 배). 이때는 누르고 있으면 끊김 없이 걷는다. 줄을 무한으로 하면 씹힘은 없지만 손을 뗀 뒤에도 계속 걷고, 더 빨리 누를수록 더 오래 걷는다.

## 4. 바꾸는 것

### 4-1. 걷는 중에 반대 방향이면 바로 되돌아선다 (로직)

- 걷는 중(`busy`이고 그 이유가 걸음)에 **지금 걸음의 반대 방향** `move`가 오면 실패하지 않고 되돌아선다.
  - 왔던 칸으로 돌아가고, 그 방향을 바라본다.
  - 걸린 시간은 지금까지 걸어온 틱만큼이다. 걸음을 시작하고 3틱 뒤에 돌아서면 3틱 뒤 원래 칸에 서 있다. 시간을 버는 일은 없다.
  - 화면은 지금 서 있는 중간 자리에서 그대로 돌아오게 그린다(걸음 시작 틱을 걸음 길이에 맞춰 옮겨 둔다).
  - 돌아오는 중에 다시 반대(처음 방향)를 누르면 또 되돌아선다. 같은 규칙이다.
- 그 밖의 방향·행동·내기는 지금처럼 걸음이 끝날 때까지 `busy`다. 일하는 중(행동·내기 6틱)에는 되돌아서기도 없다.
- 하루 규칙이라 서버도 같은 로직으로 다시 돌린다. 예전 기록에는 걷는 중 `move`가 없다(받아들여지지 않아 기록되지 않았다). 그래서 예전 입력은 새 규칙에서도 결과가 같다.

### 4-2. 바로 못 하는 조작은 덮어쓰지 않고 줄을 세운다 (화면)

- 미뤄 두는 조작을 하나(덮어씀)에서 **세 개까지의 줄**로 바꾼다. 누른 순서대로 처리하고, 앞의 것을 덮어쓰지 않는다.
- 줄이 비어 있으면 누른 조작을 바로 해 본다(지금과 같다). 줄에 무엇이 있으면 뒤에 선다.
- 줄 맨 앞은 매 프레임 해 보고, 받아들여지면 뺀다. 막힘·대상·반대 방향은 꺼내서 할 때의 상태로 판단한다(스네이크 라이브러리와 같다). 걷는 중에 맨 앞이 반대 방향이면 그 자리에서 되돌아선다(§4-1).
- **버리는 경우는 하나**: 이미 셋이 기다리는데 또 누르면 새로 누른 것을 버린다.
  - 1차 설계의 "0.5초 지나면 버림"과 "같은 행동 연타는 하나만"은 뺀다. 줄이 셋이면 기본 걸음으로도 0.45초 안에 차례가 오고, 스페이스 연타도 누른 만큼 한다.
  - 그래서 다 된 조리대를 더 누르면 누른 만큼 다음 음식 조리를 시작한다(첫 누름에 재료비). 누른 대로 한다.
- 멈춤·마감 때 줄을 비우는 것은 지금과 같다.

### 4-3. 누르고 있으면 계속 걷기는 0.15초부터 (화면)

- 방향키를 **0.15초 넘게** 누르고 있을 때만 다음 걸음을 이어 간다. 그보다 짧게 누르면 한 칸만 간다(테트리스 DAS 167ms와 같은 생각).
- 기본 걸음(0.15초)에서는 지금과 똑같이 끊김 없이 이어 걷는다. 운동화로 걸음이 짧아지면 첫 걸음 뒤에 0.15초가 될 때까지만 잠깐 서고, 그다음부터는 끊김 없이 걷는다.
- 키를 누른 시각부터 잰다. 줄에 조작이 있으면 줄이 먼저다. 톡 누른 것이 누르고 있는 키에 밀리지 않는다(pancelor와 같다).

## 5. 바꾸지 않는 것

- 걸음·행동 시간과 강화·직원 능력, 화면을 눌러 걷기(길찾기), 숫자키·스페이스·Esc 배치.
- 흉내 플레이어와 밸런스. 흉내 플레이어는 바쁠 때 입력하지 않아 되돌아서기를 쓰지 않는다.
- 저장 형식, 입력 형식(`[틱, 동작, 값]`). 줄과 누르고 있기는 화면에만 있고, 받아들여진 조작만 그 틱으로 기록하는 것은 그대로다.

## 6. 검증과 배포

- 테스트(`test/logic.test.ts`): 걷는 중 반대 방향이면 되돌아서고 걸어온 틱만큼 걸린다. 다른 방향·행동은 여전히 `busy`. 시작한 틱에 바로 돌아서면 제자리. 되돌아서기를 섞은 입력을 `replayDay`로 다시 돌려도 결과가 같다.
- 화면은 장사 화면에서 좌우 연타, 같은 방향 연타, 계단, 누르고 있기, 스페이스 연타를 직접 해 보고 §3의 줄 3 흉내와 같게 움직이는지 본다.
- 서버와 화면을 같이 배포한다. 화면만 먼저 바뀌면 되돌아서기 입력을 서버가 `busy`로 거절한다.

## 8. 구현 메모

- 설계대로 구현했다. 로직은 `applyInput`의 `move`가 바쁠 때 `canReverse`(걸음 끝 전이고, 앞 칸이 걸어온 칸)를 보고 `reverse`한다. 되돌아설 때도 `step` 사건을 낸다.
- 화면의 줄은 `DayView.queue`(`QUEUE_MAX` 3), 누르고 있기는 `HOLD_TICKS` 9틱이다. 줄에서 꺼내 해 봤는데 바빠서 못 했으면(`busy`) 기다리고, 다른 이유(빈 쟁반 칸 등)로 실패하면 뺀다. 그래야 못 하는 조작 하나가 줄을 영영 막지 않는다. 그래서 장면의 조작(`DayHandlers`)이 참·거짓 대신 실패 사유를 돌려준다.
- 장사 화면(가로 배치)에서 키 이벤트를 정해진 간격으로 넣어 확인했다(기본 걸음).
  - 좌우 11번(0.1초 간격, 0.06초 누름): 한 칸 왼쪽에서 끝남(기대와 같음). 12번이면 제자리.
  - 같은 방향 3번(0.08초 간격): 세 칸.
  - 계단(오른·아래 번갈아 4번, 0.1초 간격): 기대한 칸.
  - 위 0.7초 누르고 있기: 끊김 없이 다섯 칸. 오른쪽 0.12초 누름: 한 칸.
