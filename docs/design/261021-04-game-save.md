# 설계: 성장형 게임 저장과 이어하기 (게임 공통)

지금까지의 Magpie 게임은 한 판으로 끝났다: 시드 + 입력 기록 → 점수([판 기록과 점수 제출](./261006-08-play-submission.md)).
**성장형 게임**은 판(하루) 사이에 상태가 남는다. 첫 사례는 [붕어빵 가게](./261021-01-fish-bun.md)다.
이 문서는 성장형 게임이 공통으로 쓰는 저장·검증·셸 흐름을 정한다. 게임별 규칙은 각 게임 문서에 둔다.

---

## 1. 원칙

- **서버가 저장의 주인이다.** 클라이언트가 보낸 저장 데이터는 받지 않는다.
- 저장은 두 가지로만 바뀐다.
  1. **하루 결과**: 서버가 같은 로직으로 그날을 다시 돌려 낸 다음 날 상태.
  2. **가게 행동**(강화 구매 등): 서버가 같은 로직으로 규칙(돈, 조건)을 확인하고 적용한 결과.
- 그래서 저장은 "시작 상태 + 검증된 하루들 + 검증된 행동들"을 차례로 다시 적용하면 언제든 똑같이 다시 만들 수 있다.
- 기존 미니게임의 흐름(판 시작 → 끝에 재계산)을 그대로 쓰고, 그 위에 "판을 연 때의 저장 상태"를 더한다.

---

## 2. 저장 단위

- **하루 = 판 하나.** 하루를 시작할 때 판을 열고(시드 발급), 하루가 끝나면 입력 기록을 보내 검증받는다.
- 하루 도중에는 저장하지 않는다. 중간에 나가면 그날은 사라지고, 다시 오면 **그날 아침 상태**로 새 판을 연다.
  - 하루가 3분이라 잃는 양이 작고, 중간 저장을 하려면 하루를 조각내 검증해야 해서 복잡도가 크게 오른다.
- 하루 도중 일시정지는 된다(§5-2).

---

## 3. 로그인과 체험

| 상태 | 할 수 있는 것 |
|---|---|
| 로그인 + 닉네임 | 저장, 이어하기, 랭킹 기록(기록 모드와 같은 조건) |
| 비로그인 · 닉네임 전 | **체험**: 시작 상태로 첫날 하루만 해 볼 수 있다. 저장·랭킹 없음 |

- 체험 정산 화면에 "로그인하면 가게가 저장돼요" + 로그인 버튼(닉네임 전이면 "닉네임을 정하면 가게가 저장돼요").
- 체험에서 번 돈은 로그인 뒤 이어받지 않는다. 서버가 연 판이 아니라 검증할 수 없어서다. 로그인하면 1일째부터 저장되며 시작한다.
- 체험은 몇 번이든 다시 할 수 있다(늘 1일째).

## 4. 서버

### 4-1. 표 (`db/007_game_saves.sql`)

| 표 | 키 | 열 |
|---|---|---|
| `game_saves` | (`user_id`, `game_id`) | `version`(1부터, 바뀔 때마다 +1), `data`(저장 상태 JSON, 최대 16KB), `created_at`, `updated_at` |
| `save_actions` | `id` | `user_id`, `game_id`, `version`(적용 전 버전), `action`(JSON), `created_at`. 가게 행동 기록(분석·복구용) |
| `plays` (열 추가) | — | `save_version`(성장형만. 판을 연 때의 저장 버전, 미니게임은 NULL) |

- 하루의 입력 기록은 기존처럼 `play_replays`에 남는다. `plays` + `play_replays` + `save_actions`로 저장의 이력을 처음부터 다시 만들 수 있다.

### 4-2. 게임 로직 규격 (`shared/src/game-logic.ts`)

미니게임용 `GameLogic`과 나란히 `GrowthLogic`을 둔다.

| 항목 | 내용 |
|---|---|
| `kind: 'growth'` | 성장형 표시 |
| `maxTicks`, `maxScore`, `inputSchema` | 기존과 같다(하루 기준) |
| `stateSchema` | 저장 상태 형식(Zod). 저장 데이터에는 형식 버전을 넣는다 |
| `initialState()` | 시작 상태 |
| `migrate(data)` | 예전 형식 버전의 저장을 지금 형식으로 고친다. 형식을 바꿀 때 쓴다 |
| `replayDay(seed, inputs, state)` | 하루를 다시 돌려 `{ ok, score, ticks, nextState }`. 실패하면 사유 |
| `actionSchema`, `applyAction(state, action)` | 가게 행동을 적용해 `{ ok, state }` 또는 실패 사유(`no_money`, `locked`, `max_level` 등) |

- 하루 시작 지원금처럼 "하루를 열 때 바뀌는 것"은 `replayDay`가 맨 앞에서 적용한다. 판을 열 때 저장을 따로 고치지 않는다.

### 4-3. API

| 요청 | 본문 | 응답 |
|---|---|---|
| `GET /api/saves/:gameId` | — | `{ version, state }`. 저장이 없으면 시작 상태로 만들어(버전 1) 준다. 비로그인 `401`, 닉네임 전 `403 NICKNAME_REQUIRED`, 성장형이 아닌 게임 `400` |
| `POST /api/plays` | `{ gameId }` | 기존 + 성장형이면 판에 지금 저장 버전을 적고 응답에 `saveVersion`을 더한다 |
| `POST /api/plays/:id/finish` | `{ inputs, ticks, score }` | 기존 + 통과하면 응답에 새 저장 `save: { version, state }`를 더한다 |
| `POST /api/saves/:gameId/actions` | `{ version, action }` | `200 { version, state }`. 버전이 다르면 `409 SAVE_CONFLICT` + 최신 저장, 규칙 위반 `400 { reason }` |

**하루 끝(`finish`)의 성장형 검사** — 기존 순서(형식 → 시간 → 재계산 → 점수)에서:

1. 판의 `save_version`이 지금 저장 버전과 다르면 거절, 사유 `stale_save`(판을 연 뒤 다른 기기·탭에서 하루를 끝냈거나 강화를 샀다).
2. 재계산은 `replayDay(seed, inputs, 판을 연 때의 저장 상태)`로 한다.
3. 통과하면 **한 트랜잭션에서** 판 닫기, 입력 기록, 최고 기록 갱신, 저장 갱신(`nextState`, 버전 +1)을 한다. 저장 줄은 `SELECT ... FOR UPDATE`로 잠그고 버전을 다시 확인한다.

- 가게 행동도 저장 줄을 잠그고 버전을 확인한 뒤 적용하고, `save_actions`에 남긴다. 요청 횟수 제한은 유저당 분당 60회.
- 하루를 진행 중일 때(안 끝난 판이 있을 때) 가게 행동을 하면 그 판은 `stale_save`가 된다. 게임 화면은 하루 중에 가게 꾸리기를 열지 않는다.

### 4-4. 그 밖의 서버 변경

| 위치 | 변경 |
|---|---|
| `server/src/plays/judge.ts` | 성장형은 시간 검사를 완화(§5-2), 재계산에 저장 상태를 넘긴다 |
| `server/src/plays/logics.ts` | `GameLogic \| GrowthLogic`을 등록한다 |
| `server/src/auth/account.ts` | 탈퇴할 때 `game_saves`, `save_actions`도 같은 트랜잭션에서 지운다 |
| 관리자 | 기록 삭제(판 `admin` 거절)는 저장을 되돌리지 않는다. 저장 초기화가 필요해지면 관리자 기능에 따로 더한다 |
| `shared/src/plays.ts` | 거절 사유에 `stale_save`, 응답 형식에 `saveVersion`·`save` |

## 5. 시간과 일시정지

### 5-1. 미니게임과 다른 점

미니게임은 "실제 경과 시간과 게임 시간이 ±5초 + 10% 안"이어야 한다. 화면을 가리면 판을 끝내므로 멈춤이 없다.
성장형은 하루 도중 일시정지(전화, 다른 앱)를 허용해야 한다.

### 5-2. 성장형 시간 검사

- **게임 시간이 실제 시간보다 많으면 거절**(게임 시계를 빠르게 돌림)은 그대로 둔다: `틱 / 60 ≤ 실제 경과 + 5초`.
- 실제 시간이 게임 시간보다 긴 것은 허용한다(일시정지). 끝나지 않은 판은 하루 뒤 `abandoned`로 정리되므로 상한은 그것으로 한다.
- 일시정지 중에는 게임이 멈춰 있어 아무 입력도 할 수 없으므로, 멈춰서 얻는 이득은 "쉬기"뿐이다.
- 화면이 가려지면 게임이 스스로 일시정지한다(판을 끝내지 않는다).

## 6. 셸 (`client`)

### 6-1. 플레이 페이지

`/play/:gameId`에서 게임의 `kind`로 갈린다.

| | 미니게임 | 성장형 |
|---|---|---|
| 시작 화면 | 셸(이름, 규칙, 모드 안내, "시작") | 게임이 그린다(가게 화면) |
| 플레이 중 막대 | 남은 시간, 점수, 소리, "끝내기" | 게임 이름, 소리, **"나가기"** |
| 결과 화면 | 셸(점수, 기록 결과) | 게임이 그린다(정산, 가게 꾸리기) |
| 서버 통신 | 셸이 판 시작·끝을 보낸다 | 셸이 게임 대신 보낸다(§6-2) |

- "나가기"를 하루 도중에 누르면 "오늘 장사는 저장되지 않아요. 나갈까요?"를 묻는다. 하루가 끝난 뒤(정산·가게 꾸리기)에는 묻지 않는다.

### 6-2. 셸과 게임의 약속 (`@magpie/shared/game-module`)

게임은 서버 주소를 모른다(게임끼리 독립, 공통 기능은 공통 모듈로만 — CLAUDE.md §4-3). 셸이 서버와 이야기하는 함수를 게임에 넘긴다.

```ts
interface GrowthSession {
  mode: 'saved' | 'trial';
  load(): Promise<SaveSnapshot>;                       // { version, state }
  startDay(): Promise<{ seed: string }>;
  finishDay(result: PlayResult): Promise<DayResult>;   // 통과: 새 저장 / 거절: 사유
  act(action: unknown): Promise<SaveSnapshot>;          // 충돌이면 최신 저장과 함께 실패
  requestLogin(): void;                                // 체험 정산의 "로그인" 버튼
}

interface GrowthGameModule {
  kind: 'growth';
  mount(parent: HTMLElement, options: { session: GrowthSession; muted?: boolean; volume?: number }): Promise<GameInstance>;
}
```

- **체험**이면 셸이 같은 모양의 `session`을 브라우저 안에서 만든다: `load`는 시작 상태, `startDay`는 무작위 시드, `finishDay`는 저장 없이 통과, `act`는 쓰지 않는다(체험은 하루뿐).
- `finishDay`를 보내지 못하면(네트워크) 게임이 "저장하지 못했어요 · 다시 보내기"를 보여 준다.
  보내지 못한 하루의 기록은 브라우저(`localStorage`)에 잠시 두고, 다음에 가게를 열 때 판이 아직 열려 있으면 다시 보낸다.
- `stale_save`로 거절되면 "다른 곳에서 가게가 바뀌었어요"를 보여 주고 최신 저장으로 가게 화면을 다시 연다.

### 6-3. 로비 카드

- 로비 카드 아래 줄: "오늘 1위 N원"(기존과 같음), 로그인 상태에서 저장이 있으면 "N일째 · 내 최고 M원".
- `GET /api/games/summary`에 성장형 게임이면 `progress: { day }`를 더한다.

## 7. 막지 못하는 것

- 봇·자동 플레이는 유효한 하루 기록을 만든다(미니게임과 같다).
- 판을 열 때 시드를 주므로, 코드를 뜯어보면 그날 손님 순서를 미리 계산할 수 있다(복권 긁기 §7과 같은 급).
- 하루가 마음에 안 들면 중간에 나가서 그날을 다시 할 수 있다. 잃는 것은 시간뿐이라 막지 않는다.

---

## 8. 테스트

- 하루 끝 통과 → 저장 버전 +1, 상태 = `replayDay`의 `nextState`. 판 점수·최고 기록이 같은 트랜잭션에서 바뀐다.
- 판을 연 뒤 강화를 사거나 다른 판이 먼저 끝나면 `stale_save`.
- 가게 행동: 버전이 다르면 `409`, 규칙 위반 `400`, 통과하면 `save_actions`에 남는다.
- 시간: 틱이 실제 시간보다 많으면 거절, 실제 시간이 훨씬 길면 통과(성장형만). 미니게임 검사는 그대로.
- 저장 이력 재현: 시작 상태에서 통과한 하루들과 가게 행동을 차례로 적용하면 지금 저장과 같다.
- 탈퇴하면 저장과 행동 기록이 지워진다.

---

## 9. 결정 사항

- [ ] 저장은 서버에만 두고, 하루 단위로 검증해 갱신한다
- [ ] 하루 도중에 나가면 그날은 사라진다(중간 저장 없음)
- [ ] 체험: 비로그인·닉네임 전에는 첫날만, 로그인 뒤 이어받지 않는다
- [ ] 성장형은 일시정지를 허용하고 시간 검사를 "빨리 돌리기"만 막도록 완화한다
- [ ] 가게 행동 기록(`save_actions`)을 남긴다
