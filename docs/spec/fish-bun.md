# 스펙: 붕어빵 가게 (`fish-bun`)

설계: [261021-01 핵심 플레이](../design/261021-01-fish-bun.md), [261021-02 손님](../design/261021-02-fish-bun-customers.md), [261021-03 성장](../design/261021-03-fish-bun-growth.md), [261022-02 메뉴](../design/261022-02-fish-bun-menu.md), [261022-03 특별 손님](../design/261022-03-fish-bun-special-customers.md).
성장형 게임(`kind: 'growth'`)이라 저장·검증·셸 흐름은 [saves.md](./saves.md)를 따른다. 게임 안 간판은 "까치 붕어빵". 원작(붕어빵타이쿤3)의 이름·그림·소리·대사는 쓰지 않는다.

## 로직 (`games/fish-bun/src/logic`)

- `rules.ts`: 하루 시뮬레이션(굽기·화력·손님·판매·마감·정산)과 `replayDay`. `customers.ts`: 손님 표·만족 판정. `growth.ts`: 저장 상태·평판·강화. `menus.ts`: 메뉴 표·주문 메뉴 뽑기.
- `index.ts`: 서버용 `fishBunLogic`(`GrowthLogic`, Zod 형식). 화면은 Zod가 번들에 들어가지 않게 `rules.ts`만 가져간다.
- 정수 연산, 시드 난수, 60틱 고정 간격만 쓴다. 손님은 `"${seed}#customers"`, 황금 후보는 `"${seed}#gold"`, 진상 손님이 깰 빵틀은 `"${seed}#trouble"` 난수를 따로 쓴다.

### 하루

| 항목 | 값 |
|---|---|
| 길이 | 10,800틱(3분). 게임 시계 10:00~22:00, 1분 = 15틱 |
| 새 손님 | 10,200틱(21:20, 마감 10초 전)까지 온다 |
| 마감 | 남은 손님은 평판 변화 없이 떠나고, 진열대·빵틀에 남은 빵은 폐기(`wasted`) |
| 진행 순서 | 한 틱: 화력 → 빵틀 익힘(깨진 틀은 저절로 고쳐지는지만 본다) → 손님 기다림 → 새 손님 → 틱 +1 → (10,800이면) 마감 |
| 입력 적용 | 그 틱을 진행하기 전에 적용한다. `replayDay`는 입력의 틱까지 진행 → 적용, 끝나면 마감까지 진행해 정산 |
| 지원금 | 하루를 열 때 돈이 500원 미만이면 500원으로 채운다(`stats.subsidy`). 하루 중 돈이 바닥나 빵틀에도 진열대에도 빵이 없으면 팥 반죽 한 번은 거저 부어진다(막다른 길 방지) |

### 메뉴

| 번호 | 메뉴 | 열리는 때 | 재료비 | 빵 값(알맞음, 레시피 0단계) | 알맞음 구간(익힘 값) | 화력 50%에서 |
|---|---|---|---|---|---|---|
| 0 | 팥 | 처음부터 | 50원 | 120원 | 26,400 ~ 42,900 | 4 ~ 6.5초 |
| 1 | 슈크림 | 평판 Lv3 | 70원 | 160원 | 23,100 ~ 36,300 | 3.5 ~ 5.5초 |
| 2 | 피자 | 평판 Lv5 | 90원 | 200원 | 33,000 ~ 52,800 | 5 ~ 8초 |

- 그날 아침 평판 레벨로 열린 메뉴 수(`params.menus`)가 정해진다. 강화로 사지 않는다.
- 반죽 레시피(+20원/단계)는 모든 메뉴의 빵 값에, 빵틀 길들이기(+2,640/단계)는 모든 메뉴의 탐 시작에 더한다.
- 손님은 메뉴 한 가지를 주문한다. 주문 비율: 팥만 100 / 팥·슈크림 65:35 / 세 메뉴 50:28:22. **열린 메뉴가 팥 하나면 메뉴를 뽑지 않는다** — 그래서 평판 Lv1~2 하루는 메뉴를 넣기 전과 난수 순서·입력 값이 같아 그대로 다시 돌아간다.

### 굽기

- 빵틀 탭: 빈 틀 → 붓기(그 메뉴의 재료비, 돈 부족이면 `no_money`, 열리지 않은 메뉴면 `locked_menu`), 아랫면 굽는 중 → 뒤집기, 윗면 굽는 중 → 꺼내기(진열대 가득이면 `shelf_full`). 같은 칸은 21틱(0.35초) 안에 다시 누를 수 없다(`too_fast`).
- 화력 0~6000(=0~100%), 시작 3000. 펌프를 누르고 있으면 틱마다 +40, 떼면 화구 단계만큼 내려간다(틱당 8·6·5·3·2·0).
- 굽는 속도 = 60 + ⌊화력 / 60⌋(틱마다 그 면의 익힘에 더함). 화력 50%면 110.
- 익힘 구간: 덜 익음 < 메뉴의 알맞음 시작 ≤ 알맞음 < 메뉴의 탐 시작 + 2,640 × 빵틀 길들이기 단계 ≤ 탐(메뉴 표). 팥은 화력 50%에서 4초, 6.5초(+0.4초씩).
- 품질은 두 면 중 나쁜 쪽(탐 > 덜 익음 > 알맞음). 아랫면은 뒤집으면 더 익지 않는다.
- 황금 후보: 부을 때 천분율 50 + 20 × 황금 비법 단계(메뉴 상관없이). 윗면이 그 메뉴의 알맞음 시작 ~ +3,960(화력 50%에서 0.6초)일 때 꺼내면 황금(아랫면이 알맞을 때만). 지나면 바로 탄다.

### 손님

| 종류 | 주문 | 기다림 | 규칙 |
|---|---|---|---|
| 동네 손님 `regular` | 1~3 | 20초 | 기본 |
| 꼬마 `kid` | 1 | 20초 | 덤이 없으면 결과 상한 아쉬움 |
| 바쁜 직장인 `office` | 1~2 | 15초 | 더 늦게 온 손님에게 먼저 팔면 바로 떠남(불만 평판). 하루를 연 뒤 20초 동안은 오지 않는다(뽑힌 직장인은 동네 손님으로 바뀜. 첫 빵이 구워지기 전에 기다림이 끝나지 않게) |
| 단골 어르신 `elder` | 2~3 | 30초 | 탄 빵이 섞이면 불만. 모두 알맞음 이상이면 팁 20% |
| 먹방 크리에이터 `creator` | 3~5 | 20초 | 덜 익음·탐도 값 배율 1, 감점 없음 |
| 리뷰어 `reviewer` | 1~2 | 20초 | 평판 변화 3배 |
| 수수께끼 손님 `riddler` | 1~2 | 25초 | 메뉴를 돌려 말한다(열린 메뉴 안에서만). 맞히면 판정대로 + 팁 30% + 평판 +1 더, 다른 메뉴면 불만 |
| 관광객 `tourist` | 1~3 | 25초 | 영어·일본어로 주문(`lang`, 손님마다 시드로 정함). 맞히면 판정대로, 다른 메뉴면 불만 |
| 진상 손님 `rude` | 1~3 | 12초 | 불만이거나 기다리다 떠나면 빵틀 하나를 깬다 |

- 등장 표(평판 레벨별 간격·비율)는 `customers.ts`의 `ARRIVALS`. 간격은 간판 단계마다 8%씩 줄고 최소 60틱. 손님마다 [종류 → 메뉴(열린 메뉴가 둘 이상일 때만) → 말(관광객만) → 주문 개수] → [다음 간격] 순서로 뽑는다.

| 레벨 | 간격(초) | 동네 / 꼬마 / 직장인 / 어르신 / 먹방 / 리뷰어 / 수수께끼 / 관광객 / 진상 |
|---|---|---|
| Lv1 | 7~11 | 80 / 20 / – / – / – / – / – / – / – |
| Lv2 | 6~10 | 60 / 20 / 20 / – / – / – / – / – / – |
| Lv3 | 6~9 | 44 / 14 / 18 / 14 / – / – / 10 / – / – |
| Lv4 | 5~8 | 34 / 12 / 16 / 12 / 8 / – / 8 / 6 / 4 |
| Lv5 이상 | 4~7 | 30 / 11 / 15 / 12 / 8 / 5 / 8 / 6 / 5 |
- 카운터 3자리. 빈 자리가 없으면 다음 손님은 자리가 날 때까지 기다리고, 손님이 떠나면 다음 손님은 최소 60틱 뒤에 온다. 첫 손님은 120~240틱.
- 그날의 손님 표는 아침 평판 레벨로 정한다(하루 동안 바뀌지 않는다).

### 깨진 빵틀 (진상 손님)

- 진상 손님이 **불만**이거나 **기다리다 떠나면**(마감 때 떠남은 제외) 빵틀 하나가 깨진다: 굽는 틀 중에서, 없으면 빈 틀 중에서 `troubleRng`로 고른다. 이미 깨진 틀은 고르지 않는다.
- 굽던 빵은 폐기한다(`wasted` +1). `stats.broken` +1. 사건 `break { mold, wasted }`.
- 깨진 틀은 비어 있고 부을 수 없다. `tap`(빵틀 번호만, 메뉴 값을 붙이면 `bad_menu`)이 수리 한 번이고 **5번**이면 고쳐진다. 안 고치면 **1,200틱(20초)** 뒤 저절로 고쳐진다. 사건 `repair { mold, hits, fixed }`. 수리 누름도 6틱 간격 규칙(`too_fast`)을 따른다.

### 판매

- 진열대는 메뉴마다 따로 쌓인다(`shelves[메뉴]`). 최대 개수는 메뉴를 합친 수.
- 입력 `sell`: 값 = 8 × 메뉴 + 자리 × 2 + 덤(1). 그 메뉴 진열대의 앞에서부터 주문 개수(덤이면 +1)를 준다. 손님 없음 `no_customer`, 그 메뉴 부족 `no_stock`, 없는 메뉴 `bad_menu`.
- **주문과 다른 메뉴를 주면 불만**(받는 돈 절반, 평판 −3, 콤보 0). 화면의 [N개 주기]는 늘 주문한 메뉴를 준다.
- 만족 점수: 황금 +2, 알맞음 0, 덜 익음 −1, 탐 −2 → +2 이상 최고, 0~1 만족, −1~−2 아쉬움, −3 이하 불만. 손님 규칙을 덧씌운다.
- 팁: 수수께끼를 맞히면(메뉴가 맞고 불만이 아니면) 30%, 아니면 최고 또는 어르신(모두 알맞음 이상) 20%.
- 받는 돈: 주문한 빵(덤 제외)의 값 합. 빵 값 = 그 메뉴 값 + 20 × 반죽 레시피 단계, 품질 배율 황금 3·알맞음 1·덜 익음 0.5·탐 0.3(정수 내림). 불만이면 절반.
- 콤보: 덤을 주고 만족 이상이면 +1, 아니면 0(기다리다 떠남·먼저 안 줘서 떠남도 0). 보너스 = (값 + 팁) × min(콤보, 10) × 10%.
- 평판: 최고 +3, 만족 +2, 아쉬움 0, 불만 −3, 떠남 −2. 리뷰어 3배. 수수께끼를 맞히면 +1 더.
- `trash`: 진열대의 탄 빵을 메뉴 상관없이 모두 버린다(`trashed`).
- 정산 기록 `soldBy`: 메뉴별 판 개수(덤 포함).

### 정산과 저장 상태

- 하루 수익 = 매출 − 재료비. 하루 점수 = max(0, 하루 수익). 최고 점수 상한 1억.
- 평판은 지금 레벨의 기준점(0·30·80·160·280·450·700·1,000·1,400·2,000) 아래로 내려가지 않는다.
- 저장 상태(v1): `day`, `money`, `reputation`, `upgrades`(7종 단계), `stats`(누적 매출·판매·황금, 최고 하루 수익, 최대 콤보). 시작: 1일째, 1,000원, 평판 0. 메뉴는 평판으로 열리므로 저장 형식에 없다.

### 입력 기록

`[틱, 동작, 값]` 배열, 하루 최대 6,000개. 동작 0 `tap`(빵틀 번호 + 16 × 메뉴. 메뉴는 빈 틀에 부을 때만 붙이고, 굽는 틀에 붙이면 `bad_menu`), 1 `pump`(1 누름 / 0 뗌, 같은 값 연속은 `bad_pump`), 2 `sell`(8 × 메뉴 + 자리 × 2 + 덤), 3 `trash`. 팥은 메뉴를 넣기 전 값과 같다(`tapArg`, `sellArg`). 틱은 줄어들면 안 되고 10,800 미만(`bad_tick`).

### 강화 (가게 행동 `{ op: 'upgrade', key }`)

| key | 이름 | 단계 | 비용 | 효과 |
|---|---|---|---|---|
| `molds` | 빵틀 늘리기 | 2 | 3,000 / 12,000 (평판 Lv2 / Lv4부터) | 6 → 9 → 12칸 |
| `seasoning` | 빵틀 길들이기 | 5 | 1,500부터 2배씩 | 알맞음 구간 +0.4초 |
| `burner` | 화구 | 5 | 2,000부터 2배씩 | 떼면 떨어지는 화력 감소, 5단계 유지 |
| `recipe` | 반죽 레시피 | 5 | 2,500부터 2배씩 | 모든 메뉴 빵 값 +20원 |
| `golden` | 황금 비법 | 5 | 3,000부터 2배씩 | 황금 확률 +2%p (5 → 15%) |
| `shelf` | 진열대 | 3 | 2,000 / 6,000 / 18,000 | 12 → 16 → 20 → 24개 |
| `sign` | 간판 | 5 | 2,000부터 2배씩 | 손님 간격 −8% |

실패 사유: `max_level`, `locked`(평판 부족), `no_money`.

## 화면 (`games/fish-bun/src/scene`, Phaser 4)

- 캔버스: 세로 배치(게임 영역이 가로 × 1.15보다 세로로 길 때)는 너비 720, **높이 = 720 × 영역 비율(높이 ÷ 너비)을 1240~1640으로 자른 값**(기준 1400. 폰에서 좌우가 비지 않게, [261022-13](../design/261022-13-play-fill-screen.md)). 가로 배치는 1560 × 1000. Scale FIT. 영역이 바뀌면(회전·주소창) 같은 상태로 배치를 다시 그린다. 세로 높이 차이가 16 미만이면 다시 그리지 않는다.
  - 늘거나 준 높이: 장사 화면은 빵틀 판이 받고, 늘 때는 카운터도 최대 +80(늘어난 만큼의 절반까지)을 받는다. 펌프 줄은 늘 맨 아래(`layout.ts`의 `stretch`). 가게 화면은 가게 그림 높이(= 높이 − 700)가 받고 카드·버튼은 아래쪽 기준. 정산 화면은 카드·버튼 묶음을 세로 가운데에. 가게 꾸리기는 위에서부터(출처 줄은 맨 아래).
- **가게 화면**: 가게 앞모습(차양·"까치 붕어빵" 간판·진열창, 뒤 골목 건물은 그림 영역 안에서 자름), 몇 일째·가진 돈·평판 막대·최고 하루 수익, [장사 시작] [가게 꾸리기]. 가로 배치는 상태 카드 높이를 내용에 맞추고(340) 카드와 버튼 묶음을 세로 가운데에 둔다. 체험이면 안내 줄, 체험 하루를 마치면 [로그인하고 저장하기] [다시 체험하기].
- **장사 화면**(`DayView.ts`): 위 시계 막대(날짜·게임 시계·평판·돈·멈춤), 카운터(시간에 따라 하늘색이 바뀜, 차양, 손님 3자리), 진열대(왼쪽이 먼저 나가는 빵, 품질은 색 + 별·점선·연기 모양) + [탄 빵 버리기], 빵틀(6칸까지 2열, 그 뒤 3열), 펌프·화력 계기·콤보(가로 배치는 오늘 매출·손님 기록 칸 추가).
  - 반죽 고르기(메뉴가 둘 이상 열린 날만): 빵틀 판 위 [팥] [슈크림] [피자] 버튼(메뉴 아이콘·반죽 값). 고른 반죽이 빈 틀에 부어지고(쓸어 넘기기도 같은 반죽), 하루를 열면 팥. 배치를 바꿔 다시 그려도 고른 반죽은 유지.
  - 메뉴 표시(메뉴가 둘 이상 열린 날만): 굽는 빵틀 왼쪽 위와 진열대 빵 왼쪽 위에 작은 메뉴 아이콘(팥 콩, 슈크림 크림 방울, 피자 조각). 부은 반죽은 가운데 속이 보인다(팥소·노란 크림·빨간 소스와 치즈·피망). 뒤집은 붕어빵은 메뉴와 상관없이 같은 모습. 진열대는 메뉴별로 모아(팥 → 슈크림 → 피자) 놓는다.
  - 손님: 말풍선(성격 아이콘 + 메뉴 아이콘(메뉴가 둘 이상일 때, 성격 아이콘보다 크게) + 주문 개수 + 대사 2.2초. 대사도 메뉴를 말한다: "슈크림 두 개 주세요"),
    - 대사가 두 줄을 넘으면(예: 리뷰어 "슈크림 두 개 주세요, 리뷰 쓰러 왔어요") 말풍선을 위로 키워 대사 아래 끝을 맞춘다. 꼬리 위치는 그대로.
    - 특별 손님 성격 아이콘: 수수께끼 "?", 관광객 지구본, 진상 번개. 수수께끼 손님·관광객은 메뉴 아이콘 대신 "?"(수수께끼는 성격 아이콘 하나), 말풍선을 위로 키우고 단서 대사(수수께끼·영어·일본어)를 지우지 않는다(기다림 대사도 하지 않는다). 일본어는 글자 단위로 줄을 바꾼다.
    - 메뉴 고르기: 수수께끼 손님·관광객의 [N개 주기]·[+1 덤]은 "메뉴 고르기"(열린 메뉴 중 하나라도 넉넉하면 켜짐). 누르면 그 손님 위에 열린 메뉴 버튼(메뉴 아이콘·이름·진열대 개수, 모자라면 꺼짐)이 뜨고, 고르면 그 메뉴로 판다. 다른 곳을 누르거나 손님이 떠나면 닫힌다. 틀리면 손님이 정답을 말하고 떠난다("슈크림, 그게 정답이었는데…", "Oh, I wanted custard…"). 기다림 막대(30% 남으면 대사 한 번), [N개 주기](주문한 메뉴를 준다. 받을 돈 미리 보기, 모자라면 "슈크림 1개 부족") [+1 덤]("+1 덤" 한 줄 글자, 꼬마면 깜빡임). 말풍선 윗줄(성격 아이콘 + 메뉴 아이콘 + 개수)은 상자 가운데에 한 묶음으로 놓고, 판매·떠남 때는 개수·아이콘을 치우고 대사만 상자 가운데에 둔다. 판매·떠남 때 표정(기쁨·보통·화남)과 대사, 받은 돈·콤보·평판이 떠오른다.
  - 빵틀: 익힘에 따라 두 그림을 섞어 색이 서서히 바뀐다. 알맞음엔 김, 탐엔 연기. 황금 후보는 꼬리·등지느러미 모양만 다르고, 반짝이는 동안에만 금색 + 빛.
  - 깨진 빵틀: 금 간 그림(고칠수록 3 → 1단계로 줄어든다)과 "N번 눌러 고치기". 깨질 때 "쾅!"(제목 글꼴), 화면 흔들림, 연기·조각, "쨍그랑" 소리. 두드릴 때 금이 흔들리고 망치 "땅", 다 고치면 김과 "다 고쳤어요".
  - 조작: 빵틀 탭, 쓸어 넘기기(처음 누른 칸과 같은 단계의 칸만, 깨진 칸은 건너뛴다. 깨진 칸은 하나씩 눌러 고친다), 펌프 누르고 있기(손가락 3개까지). 마감 30초 전부터 시계·막대가 주황. 화력 계기 글자는 칸에 들어가는 가장 긴 문구("화력 50% · 속도 ×1.1" → "화력 50% · ×1.1" → "50% · ×1.1").
- 오늘 장사 그만두기: 그날 입력·정산은 보내지도 남기지도 않고 가게로 돌아간다(저장 상태는 그대로).
- **정산 화면**: "N일차 장사 끝" 제목, 매출·재료비·순 수익·지원금, 손님 수와 결과(최고·만족·아쉬움·불만·떠남)·최대 콤보·황금·폐기·깨진 빵틀을 이름 왼쪽·값 오른쪽 줄로, 팥 말고도 팔았으면 메뉴별 판 개수, 평판(레벨업이면 새 메뉴·새 손님·새 강화 안내), 저장 상태 줄. 저장하면 [가게 꾸리기] 하나만 둔다(강화를 놓치고 바로 다음 날로 넘어가지 않게. 장사는 가게 화면에서 시작), 저장 실패면 [다시 보내기]. 내용이 화면보다 길면 카드·버튼 묶음을 통째로 줄여 한 화면에 넣는다(스크롤 없음).
- **가게 꾸리기**: 강화 7종 카드(그림·단계 점·지금 → 다음 효과·비용 버튼, 평판 부족이면 "평판 LvN부터", 체험이면 "로그인 필요").
- **소리 설정**(`scene/settings.ts`, 셸 머리줄이 없어서 게임 안에 둔다): 가게 화면 오른쪽 위 톱니 → 설정 창("설정", 소리 [켜짐/꺼짐], 음량 [-] 10칸 막대 [+], [닫기], 바깥을 눌러도 닫힘). 멈춤 창에도 같은 소리 줄. 음량을 0까지 내리면 꺼짐(음량은 기억), 꺼진 상태에서 [+]면 기억한 음량으로 켜짐. 바꾸면 `onSoundChange`로 셸에 알린다.
- 체험 안내 줄: "체험 중 · " + 셸이 준 `trialHint`.
- 멈춤 창: [계속하기] [오늘 장사 그만두기]. 화면이 가려지면 자동으로 멈춘다. 마감하면 "마감!" 뒤 1.3초 후 정산.
- 하루 시계는 프레임 시간(한 프레임 최대 250ms)을 멈춘 시간 없이 더해 틱을 센다. 게임 시간이 실제보다 느려질 수는 있어도 빨라지지 않는다.
- 그림은 모두 자체 SVG(`art.ts`, `people.ts`: 손님 9종 × 생김새 2 × 표정 3. 수수께끼 손님은 탐정 모자·돋보기 / 물음표 비니·큰 안경, 관광객은 챙 모자·카메라 / 모자·지도, 진상 손님은 찌푸린 눈썹·팔짱). 대사는 `lines.ts`(요즘 말투, 상황마다 여러 개). 소리는 Web Audio 합성(`sound.ts`): 붓기·뒤집기·꺼내기·탐·반짝임·판매(콤보에 따라 음 상승)·화남·문 종·지글지글(굽는 칸 수)·펌프·팡파르.

### 도트 그림체 (`scene/style.ts`)

설계: [261022-01-fish-bun-pixel-art.md](../design/261022-01-fish-bun-pixel-art.md).

- `ART_STYLE = 'pixel'`(지금). `'smooth'`로 바꾸면 도트로 바꾸기 전 SVG 그림으로 돌아간다(백업). 바꾸기 전 전체 모습은 git 태그 `fish-bun-svg-art`.
- **그림 도트 굽기**: SVG를 구운 뒤 1/칸 크기로 줄이고 → 투명도를 딱 자르고(110 미만 투명) → 많이 쓰인 색 16개로 줄이고(비슷한 색은 합침) → 바깥에 어두운 갈색(#2a1a10) 테두리 한 칸 → 원래 크기로 키운다. 텍스처 크기는 그대로다.
  - 칸 크기: 붕어빵·빵틀·손님·펌프 4px, 진열대 아이콘·아이콘·동전·간판 까치 3px.
  - 김·연기는 도트 원 조각, 반짝이는 도트 십자. 황금 빛(glow)만 부드러운 빛 그대로.
- **화면 그리기**: 패널·버튼·말풍선·쟁반·화구 판은 계단형 모서리(4px 칸, 반지름에 따라 0~2단)와 한 칸 테두리, 하늘은 8단 색 띠, 원(차양 물결·전구·해·단계 점)은 칸 단위 원, 막대(진행·기다림·화력·평판)는 각진 막대 + 칸 구분 줄. 말풍선 꼬리는 계단 삼각형.
- Phaser `render.smoothPixelArt`: 확대해도 칸이 뭉개지지 않고, 소수 배율에서 칸 경계만 부드럽게 한다.
- **글꼴**: 게임 안 글자는 갈무리11 굵은 꼴(Galmuri11-Bold, OFL-1.1, npm `galmuri`). 그 파일 하나(약 170KB, 한글 11,172자 모두 있음)를 모든 굵기에 쓰고, 이 게임을 열 때만 `FontFace`로 불러온다. 글자 크기는 11px 격자의 배수(최소 22px)로 맞춘다. 셸 화면은 Pretendard 그대로. 빼기 기호는 글꼴에 없는 "−" 대신 "-".
- **제목 글꼴**(설계 [261022-04](../design/261022-04-fish-bun-title-font.md)): 제목·큰 숫자는 **던파 비트비트체 v2**(넥슨 서체, `titleStyle`). 간판 "까치 붕어빵", "N일째 아침", "가게 꾸리기", 콤보 숫자, "마감!", "N일째 장사 끝", "잠깐 쉬는 중".
  - 파일: `games/fish-bun/assets/fonts/dnf-bitbit-v2/DNFBitBitv2.otf` — 넥슨 배포 zip의 OTF를 **고치지 않고** 그대로 둔다(약 1.8MB, 같은 zip의 TTF는 3.2MB). 서브셋·woff2 변환·이름 바꾸기를 하지 않는다. 넥슨 약관과 출처는 같은 폴더 `NOTICE.md`.
  - 갈무리11과 함께 게임을 열 때 불러온다. 못 받으면 갈무리11로 그린다. 보통 꼴 하나뿐이라 굵게(가짜 굵기)를 쓰지 않는다. 계단이 모양으로 그려진 글꼴이라 크기를 격자에 맞추지 않는다.
  - 출처 표기: 가게 꾸리기 화면 맨 아래 "글꼴: 던파 비트비트체 v2(넥슨), 갈무리11".
  - 배포: nginx가 `.otf`를 `font/otf`로 내보내고 압축(gzip) 대상에 넣어야 전송이 약 0.5MB로 준다(압축은 전송 단계라 파일 수정이 아니다).
  - `ART_STYLE = 'smooth'`면 쓰지 않는다(Pretendard).
- **일본어 글꼴**(관광객 일본어 대사): 갈무리11 보통 꼴(`galmuri/dist/Galmuri11.woff2`, 약 500KB, 가나·한자 포함)을 `Galmuri11R` 이름으로, 굵게 없이(`jaTextStyle`) 그린다. 굵은 꼴에는 가나가 없다. **평판 Lv4 이상일 때만** 받는다: 게임을 열 때(저장 평판 기준)와 하루를 열 때(`prepareDay`). 중국어는 갈무리에 없는 간체자가 있어 넣지 않았다.
